FC-SAN

What is a SAN & Why It Exists

🧩 Big Picture Analogy Analogy
Think of storage like a city's water system. In DAS (Direct-Attached Storage), each house has its own private well — you own all the water, but you can't share it, and if your pump breaks, you're out of water. A SAN is like connecting every house to a shared city waterworks — the water (storage) is centralized, multiple houses (servers) can draw from it simultaneously, and you can extend pipes across the entire city or even to the next town.
⚙️ Technical Explanation Technical

A Storage Area Network (SAN) is a dedicated, high-speed network whose primary purpose is to connect compute systems to storage systems (and storage systems to each other). Key points:

  • Multiple compute systems can share and access the same storage resources simultaneously.
  • It provides block-based storage access (unlike NAS which provides file-based).
  • A SAN can span wide geographic distances, enabling remote replication, remote backup, and disaster recovery across sites — no more shipping backup tapes.
  • SAN overcomes DAS limitations: DAS is private per server, wastes capacity, and is hard to scale. SAN consolidates storage so overall utilization improves and management becomes centralized.
Why it matters: Without SAN, organizations waste 30–70% of their storage capacity because each server over-provisions to avoid running out. SAN enables true storage pooling, which is foundational to cloud infrastructure.

Types of Network Communication (the big picture)

TypeWhat it connectsProtocol used
Compute-to-ComputeServers talking to serversIP (LAN/WAN)
Compute-to-StorageServers talking to storageFC, iSCSI, FCoE
Inter-CloudClouds talking to cloudsWAN / Internet

Third Platform Requirements for SAN

The "Third Platform" (cloud + mobile + social + big data) demands SANs that are faster, more scalable, and more automated than traditional infrastructure. This is the business driver behind all of FC-SAN, IP-SAN, and SDN.

Software-Defined Networking (SDN)

🧩 Big Picture Analogy Analogy
A traditional network switch is like a traffic cop who is permanently stationed at an intersection with hardwired instructions baked into his brain. SDN is like replacing that cop with a remote-controlled robot — now a central controller (a smart dispatcher downtown) can reprogram all the robots across the entire city instantly, without physically going to each intersection.
⚙️ Technical Explanation Technical

Every traditional switch/router has two planes:

  • Data Plane — physically moves traffic from port to port, following rules.
  • Control Plane — the "brain" that decides the rules. Normally hardcoded in firmware.

SDN separates the control plane from the data plane. The control logic moves out of each individual switch and into an external software Network Controller running on a compute system or dedicated device.

Application requirement changes → Admin updates policy in Network Controller → Controller pushes rules to all switches simultaneously → Fabric reconfigures automatically

SDN Benefits in SAN

BenefitWhat it means
Centralized ControlOne point to manage the entire fabric, even across multiple data centers
Policy-Based AutomationOperations like zoning can be automated based on business rules — no manual, error-prone changes
Simplified, Agile ManagementStandardized management interface, less operational complexity, faster response to application needs

FC SAN — Components, Cables & Interconnecting Devices

🧩 Big Picture Analogy Analogy
Think of FC SAN infrastructure like a high-speed train network. The HBA is the ticket machine at each station (compute system) that converts passengers (SCSI data) into a format compatible with the train. The cables are the tracks — multimode is the local metro with limited range, single-mode is the intercity express. The FC switch is the junction station that routes trains toward their destination. The director is the major hub station with full redundancy and massive capacity.
⚙️ What is Fibre Channel? Technical

Fibre Channel (FC) is a high-speed network technology that combines the performance of a channel (low overhead, fast, deterministic) with the flexibility of a network (scalable, long distance). It transports SCSI commands, data, and status over optical fiber or copper.

Key FC Speed Numbers 🔢
  • Ultra640 SCSI (old DAS): 640 MB/s
  • 16 GFC (current): 3,200 MB/s throughput (raw: 16 Gb/s)
  • 32 GFC (projected 2016): 6,400 MB/s
  • 128 GFC (projected 2016): 25,600 MB/s
  • Theoretical max devices on one FC SAN: ~15 million

Network Adapters

  • FC HBA (Host Bus Adapter) — installed in a compute system. Has SCSI-to-FC processing capability. It takes SCSI I/Os from the OS/hypervisor and encapsulates them into FC frames before sending them to the SAN.
  • Storage system front-end adapters — on the storage side, same idea.

FC Protocol Stack (FC-0 to FC-4)

🧩 Big Picture Analogy Analogy
The FC protocol stack is like mailing a package. FC-4 is you writing the letter (application commands). FC-2 is the envelope with the address and contents organized. FC-1 is the post office encoding it into bar codes for the machine to read. FC-0 is the physical truck and road that physically moves the package.

The Five Layers

LayerNameFunction
FC-4Protocol Mappings (Top)Maps Upper Layer Protocols (ULPs) to FC — e.g., SCSI, IP, ATM, ESCON, HIPPI. This is where SCSI commands live.
FC-3(Not implemented)Originally reserved for common services — skipped in practice
FC-2Framing & SignalingFC addressing, frame structure (frames/sequences/exchanges), fabric services, classes of service, flow control, routing
FC-1Encoding/DecodingEncodes 8-bit → 10-bit for transmission (or 64-bit → 66-bit for 10 Gbps+). Defines frame delimiters, primitive signals, link initialization, error recovery.
FC-0Physical Interface (Bottom)Cables, connectors, optical/electrical specs, bit transmission. Defines what you can physically plug in.
Key insight: FC is a channel+network hybrid. Channels (like SCSI) are fast but limited in distance/scalability. Networks (like IP) are flexible but have overhead. FC gives you channel speed and network scalability. SCSI data is wrapped (encapsulated) in FC frames — so storage devices on the SAN look like locally attached disks to the OS.

FC Addressing & WWN

FC Address (Dynamic)

Every node port that logs into the fabric gets a 24-bit FC address dynamically assigned. Structure:

FieldBitsMeaningValues
Domain ID8Identifies the switch239 usable (some reserved for fabric services)
Area ID8Identifies a group of ports on the switch (e.g. a port blade)256 possible
Port ID8Identifies the specific port within the area256 possible
Max FC fabric size: 239 × 256 × 256 = 15,663,104 node ports

Reserved FC addresses:

  • FFFFFC — Name Server
  • FFFFFD — Fabric Controller
  • FFFFFE — Fabric Login Server
  • FFFFFA — Management Server

WWN — World Wide Name (Static)

Like a MAC address in IP networking. A 64-bit, globally unique, permanent identifier burned into hardware (or assigned via software).

TypeWhat it identifies
WWNN (World Wide Node Name)Identifies the FC adapter itself (e.g., the HBA card)
WWPN (World Wide Port Name)Identifies each port on that adapter
Example: A dual-port FC HBA has 1 WWNN (one card) and 2 WWPNs (two ports). WWNs are used in zoning and LUN masking configurations. The Name Server keeps a live mapping of WWN ↔ FC address.
FC address vs. WWN: FC address = like your seat number at a restaurant (changes each visit). WWN = like your national ID number (permanent, always yours).

Flow Control — BB_Credit

Imagine a warehouse with a loading dock. The dock has 5 parking bays (receive buffers). Each time a truck (frame) arrives and parks, that's 1 bay used. When the truck unloads and leaves, the dock sends a "bay free" signal (R_RDY) back to the sender. The sender keeps a count of free bays — if it's 0, it parks its trucks (holds frames) until a bay opens. This prevents trucks from crashing into a full dock (no dropped frames).

BB_Credit (Buffer-to-Buffer Credit) is FC's flow control mechanism. It ensures a transmitter never floods a receiver that can't keep up.

During port login, transmitter and receiver agree on credit count (# of receive buffers) → Transmitter sends a frame → Credit count decrements by 1 → Receiver processes frame, frees buffer → Receiver sends R_RDY back → Transmitter credit increments by 1 → Transmission continues
If credit reaches 0 → transmission is suspended until R_RDY is received. No frames are ever dropped due to buffer overflow. This is why FC is deterministic and reliable for storage traffic.

FC Fabric Topologies

Single-switch = one big hub airport, every flight lands here. Full mesh = every airport has direct flights to every other airport. Partial mesh = some airports connect directly, others need a connection. Core-edge = a few major hub airports (core directors) with many small regional airports (edge switches) feeding into them.
TopologyStructureProsCons
Single-SwitchOne switch (typically a director); all compute and storage connect to itNo ISLs needed → all ports available for nodes; zero ISL delaysLimited by port count of one switch; not infinitely scalable
Full MeshEvery switch connects to every other switchMax 1 ISL hop between any two nodes; low latencyISL port count grows rapidly with number of switches; best for ≤4 switches
Partial MeshNot all switches are interconnectedMore scalable than full meshMultiple hops possible; ISL overload risk if traffic poorly distributed
Core-EdgeTwo tiers: Edge (switches, cheap) + Core (directors, redundant); storage on core; compute on edge or coreScales well; compute-to-storage crosses only 1 ISL; conserves ports; easy expansionMore complex design; core must be highly available
Core-Edge detail: Edge switches connect to core directors via ISLs but NOT to each other. All storage is on the core. High-performance compute can connect directly to core to avoid ISL delay. To expand: add edge switches to existing core, or add more core switches (single-core → dual-core).

Link Aggregation

Instead of one busy highway lane, link aggregation creates a multi-lane expressway by combining several lanes (ISLs) into one logical road (port-channel). All cars (traffic flows) distribute across all lanes — no single lane gets jammed.

Link aggregation bundles two or more parallel ISLs into a single logical ISL called a port-channel.

  • Traffic is distributed across all ISLs in the port-channel — prevents any single ISL from becoming a bottleneck.
  • Port-channel count scales with application demand.
Example: 10 ISLs × 16 Gb/s each = 160 Gb/s port-channel throughput

Without link aggregation: traffic is assigned to ISLs in round-robin → some ISLs become overloaded while others are idle. With link aggregation: traffic for any node pair distributes across all ISLs → even utilization.

Zoning

Zoning is like creating private rooms in a large open-plan office. Only people in the same room can talk directly to each other. Even though everyone is in the same building (same SAN fabric), a developer in Room A cannot see or talk to the accounting data in Room B. The building manager (fabric controller) only sends building-wide announcements to the rooms they actually affect.

Zoning is an FC switch function that logically segments node ports into groups. Only members within the same zone can communicate.

Why Zoning Matters

  • Access Control: Prevents unauthorized compute systems from accessing storage systems they shouldn't see. Works alongside LUN masking for layered security.
  • RSCN Reduction: Without zoning, when anything changes in the fabric, the Fabric Controller sends RSCNs (state change notifications) to every single node — lots of unnecessary management traffic. With zoning, RSCNs only go to nodes within the affected zone. Critical for large fabrics.

Zoning Hierarchy

LevelWhat it is
Zone SetA group of zones activated/deactivated together as one entity. Only ONE zone set can be active at a time, but multiple sets can exist.
ZoneA group of members that can communicate with each other
MemberA port/node in the zone (switch ports, HBA ports, storage ports). A port can belong to multiple zones.

Types of Zoning

IP SAN Overview — Why Use IP for Storage?

FC SAN is like a dedicated private toll highway — extremely fast, but expensive to build and limited to where you lay the tracks. IP SAN is like using the existing public road network — already everywhere, connected to everything, no distance limit, and you already paid for it through your internet bill.

IP SAN uses Internet Protocol (IP) to transport block storage traffic. Two main protocols:

  • iSCSI — transports SCSI commands over IP/TCP. Native IP storage networking.
  • FCIP — tunnels existing FC frames over IP. Used to connect distant FC SANs.

Why IP SAN?

ReasonExplanation
Existing infrastructureMost organizations already have IP networks — reuse them for storage, avoiding cost of new FC infrastructure
No distance limitationIP has no inherent distance constraint — extend storage networking globally
Disaster RecoveryMany DR solutions already use IP; mature security options available for IP networks

iSCSI — What It Is & Components

iSCSI is like putting a parcel (SCSI commands/data) into a standard postal envelope (TCP/IP packet) and mailing it through the existing post office network (IP network). The parcel arrives, gets unwrapped, and the storage system handles it just like any normal storage command.

iSCSI (Internet SCSI) encapsulates SCSI commands and data into TCP/IP packets and transports them over a standard IP network. The storage system on the other end unwraps the IP packet and processes the SCSI command as normal.

IP-SAN

iSCSI Connectivity Types

Native iSCSI

  • Compute connects directly to iSCSI storage over IP
  • Storage system has iSCSI ports
  • No FC components needed
  • Initiator logs on to IP network → accesses LUNs directly

Bridged iSCSI

  • Compute is on IP network, storage is on FC SAN
  • A gateway / multiprotocol router bridges between the two worlds
  • Gateway has both Ethernet and FC ports
  • Initiator targets the gateway's IP address. Gateway converts IP ↔ FC frames.
  • Gateway acts as an FC initiator toward the storage system
Most modern storage systems have both FC and iSCSI ports, so they can serve both FC clients and iSCSI clients simultaneously.

FCIP — Fibre Channel over IP

Imagine two private FC train networks (SANs) separated by a vast ocean. FCIP is like building a ship container (IP tunnel) that loads the FC trains onto it, sails across the ocean (IP network), and delivers them to the other train network — without changing the trains at all. The trains don't even know they crossed an ocean.

FCIP (Fibre Channel over IP) is a tunneling protocol that encapsulates entire FC frames inside IP packets to connect geographically separated FC SANs over an existing IP network.

  • FC frames are not altered — they are just wrapped in IP.
  • Creates virtual FC links over IP — the fabrics on each end see FCIP gateways as if they were regular FC switches.
  • The nodes in each fabric are unaware of the IP network in between.
  • Primary use case: disaster recovery (replicating data to a remote site), long-distance data sharing.

How FCIP Works

FC SAN Site A → FCIP Gateway A (encapsulates FC frames into IP packets) → IP Network → FCIP Gateway B (strips IP wrapper, passes FC frames) → FC SAN Site B
An IP address is assigned to the FCIP gateway's IP-facing port. The gateway's FC-facing port connects to the local FC fabric via a standard FC connection. Gateways appear as fabric switches to the FC fabric.

FCIP Tunnel Configuration

An FCIP tunnel consists of one or more independent TCP/IP connections between two FCIP gateway ports (tunnel endpoints). Multiple tunnels can exist between the same two fabrics. Tunnels can be aggregated for throughput and redundancy.

Two Tunnel Modes

ModePorts usedEffectWhen to use
Merged FabricE_Port + VE_Port on gatewayThe two FC SANs merge into ONE large logical fabric. Fabric services are shared across the IP link.When you want transparent fabric extension
FC-FC Routing (Non-Merged)EX_Port + VE_Port on gatewayFabrics stay separate. Only selected nodes can communicate across the tunnel. EX_Port allows routing but doesn't propagate fabric services to the other fabric.When only a subset of nodes need cross-site access; better isolation
VE_Port (Virtual E_Port) = behaves like an E_Port but exclusively used for FCIP tunnel endpoints. EX_Port = like E_Port but doesn't share fabric services between fabrics — used for FC-FC routing without merging.

Exam Q&A — Test Yourself

🧪 FC-SAN Questions
Q1: What is the difference between a WWN and an FC address?
A: WWN is a static, permanent 64-bit identifier burned into hardware (like a MAC address). FC address is dynamically assigned when a node logs into the fabric — it can change. WWN is used for identity; FC address is used for routing within the fabric.
Q2: A dual-port FC HBA has how many WWNNs and WWPNs?
A: 1 WWNN (identifies the adapter/card) and 2 WWPNs (one per port).
Q3: What is the maximum number of node ports in a single FC switched fabric, and how is it calculated?
A: 239 domain IDs × 256 areas × 256 ports = 15,663,104 ports. (239 because some domain IDs are reserved for fabric services like name server at FFFFFC.)
Q4: What is BB_Credit and why does FC use it?
A: BB_Credit (Buffer-to-Buffer Credit) is FC's flow control mechanism. It ensures the transmitting port never sends more frames than the receiving port has buffer space for. When credit = 0, transmission pauses. This prevents frame drops without requiring TCP-style retransmission. When the receiver frees a buffer, it sends R_RDY back to increment the sender's credit.
Q5: What are the three types of zoning and which is most flexible when nodes move between switch ports?
A: WWN zoning, Port zoning, Mixed zoning. WWN zoning is most flexible for node moves — since WWN is tied to the hardware (not the port), the zone config needs no change when a node moves to a different switch port.
Q6: In core-edge topology, where are storage systems connected, and why?
A: Storage systems are connected to the core tier (directors). This ensures compute-to-storage traffic only crosses one ISL (from edge switch to core director) regardless of where the compute system is, minimizing latency and ISL hops.
Q7: What is the sequence of login events when a compute system connects to an FC SAN?
A: (1) FLOGI — node logs into fabric, gets FC address from Fabric Login Server (FFFFFE). (2) Node registers with Name Server (FFFFFC). (3) Node queries Name Server for targets. (4) PLOGI — node establishes session with specific target. (5) PRLI — nodes exchange SCSI-specific parameters to begin I/O.
Q8: What is the purpose of RSCNs and how does zoning reduce their impact?
A: RSCNs (Registered State Change Notifications) are sent by the Fabric Controller when something changes in the name server database (e.g., a node joins or leaves). Without zoning, RSCNs go to every node — unnecessary traffic for nodes that don't care about the change. With zoning, RSCNs only go to nodes within the affected zone, significantly reducing management traffic in large fabrics.
Q9: Why is multimode fiber limited to shorter distances than single-mode fiber?
A: MMF sends multiple light beams at different angles. These beams travel different path lengths inside the cable and arrive at slightly different times — called modal dispersion. The overlapping and collision of beams weakens the signal. SMF sends a single ray of light through the center of a much smaller core, eliminating modal dispersion and allowing distances up to 10 km.
Q10: What does SDN (Software-Defined Networking) do to the traditional switch architecture?
A: SDN separates the control plane from the data plane. Normally, each switch has its own control logic hardwired in firmware. SDN moves the control logic to an external Network Controller software. The controller manages all switches centrally, enabling policy-based automation, faster reconfiguration, and simplified management across the entire fabric.
🧪 IP-SAN Questions
Q11: What is the key difference between iSCSI and FCIP?
A: iSCSI is a native IP storage protocol — it encapsulates SCSI commands into TCP/IP to provide IP-based storage access to compute systems (replacing or supplementing FC). FCIP is a tunneling protocol — it wraps existing FC frames inside IP to extend FC SAN connectivity over long distances. iSCSI talks to storage directly; FCIP connects FC fabrics to each other.
Q12: An iSCSI HBA vs. a standard NIC — what's the critical difference?
A: A standard NIC with software iSCSI adapter makes the CPU handle all TCP/IP processing AND iSCSI encapsulation — CPU becomes a bottleneck under heavy storage I/O. An iSCSI HBA handles all of this in dedicated hardware, offloading the entire TCP/IP + iSCSI stack from the CPU, giving much better performance.
Q13: What is bridged iSCSI and when is it used?
A: Bridged iSCSI is used when the compute systems are on an IP network but the storage systems are on an FC SAN (without iSCSI ports). A gateway device with both Ethernet and FC ports bridges the two. The initiator targets the gateway's IP address; the gateway converts IP packets ↔ FC frames and acts as an FC initiator toward the storage system.
Q14: What is the iSCSI equivalent of the FC Name Server?
A: iSNS (Internet Storage Name Service). Both are discovery services — the Name Server registers FC node ports and maps WWNs to FC addresses; iSNS registers iSCSI initiators and targets and allows initiators to find available targets automatically.
Q15: What is the difference between a merged fabric and FC-FC routing in FCIP?
A: In merged fabric, two FC SANs join into one large logical fabric — fabric services are shared across the FCIP tunnel using VE_Ports (virtual E_Ports on both gateways). In FC-FC routing (non-merged), the fabrics remain separate and only specific nodes can communicate across the tunnel — achieved using EX_Ports, which allow routing without propagating fabric services between the two fabrics. Use FC-FC routing when you want isolation and only partial cross-site access.
Q16: What is an IQN and what are its three parts?
A: IQN = iSCSI Qualified Name. Format: iqn.YYYY-MM.reverse-domain:optional_string. Three parts: (1) iqn. prefix, (2) date (year-month) to prevent conflicts when domains change ownership, (3) reversed registered domain name, followed by an optional string (serial number, asset tag, etc.).
Q17: Why does FCIP potentially cause IP packet fragmentation, and how is it handled?
A: FC frames can be large. When encapsulated inside an IP packet, the resulting IP packet may exceed the MTU (Maximum Transmission Unit) of the underlying data link (Ethernet). This causes the IP packet to be fragmented into smaller pieces. TCP handles receiving and re-sequencing these fragments before passing the reconstructed data to the FC processing layer.
