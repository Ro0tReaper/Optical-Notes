14.1

Automation Overview

💡
Core idea: Automation removes repetitive manual work from humans and hands it to machines/software — faster, consistent, and at scale.

🤖 Why Automate?

  • Machines work 24/7 without breaks → greater output
  • Produces a more uniform, consistent product
  • Enables collection of vast data that can be analyzed quickly
  • Reduces human risk in dangerous environments (mining, fire, industrial accidents)
  • Smart devices can alter behavior based on environment (energy saving, medical diagnosis, driving safety)

🧠 Thinking / Smart Devices

  • A smart device takes action based on outside information
  • Examples: smart appliances reducing power during peak demand, self-driving cars
  • Devices "think" by being programmed with network automation tools
  • The word smart in a product name = ability to alter behavior based on environment
14.2

Data Formats

📦
What is a data format? A structured, standardized way to store and exchange data between applications. Common formats used in network automation: JSON, YAML, XML. The format chosen depends on what the application/tool supports; many support multiple.

📐 Data Format Rules (apply to all formats)

  • Syntax — brackets [ ] ( ) { }, white space, indentation, quotes, commas
  • Objects — characters, strings, lists, arrays
  • Key/Value pairs — key (left) identifies/describes the data; value (right) is the data itself
  • Values can be: character, string, number, list, or another object
JSON
  • Human-readable
  • Uses { } for objects, [ ] for arrays
  • Keys must be in double quotes
  • Key/value separated by colon
  • Multiple pairs separated by commas
  • White space is not significant
  • Most popular for web APIs
  • Easy to parse in Python
YAML
  • Human-readable
  • Superset of JSON
  • Minimalist — no brackets or commas
  • Uses indentation to define structure
  • Key/value separated by colon, no quotes
  • List items prefixed by a hyphen ( - )
  • Easiest to read/write
XML
  • Human-readable
  • Similar to HTML
  • Self-descriptive — data enclosed in tags
  • Syntax: <key>value</key>
  • No predefined tags — custom tags
  • Lists use repeated tag instances
  • Most verbose of the three

🔍 Same Data — Three Formats (ISS Position example)

// JSON
{
  "message": "success",
  "timestamp": 1560789260,
  "iss_position": {
    "latitude": "25.9990",
    "longitude": "-132.6992"
  }
}
# YAML
message: success
timestamp: 1560789260
iss_position:
  latitude: '25.9990'
  longitude: '-132.6992'
<!-- XML -->
<root>
  <message>success</message>
  <timestamp>1560789260</timestamp>
  <iss_position>
    <latitude>25.9990</latitude>
    <longitude>-132.6992</longitude>
  </iss_position>
</root>

🔑 JSON Deep Dive — Arrays

When a key has multiple values → that's an array. Array rules:

  • Key followed by colon, values enclosed in square brackets [ ]
  • Array is an ordered list of values
  • Can contain: strings, numbers, Booleans, objects, or other arrays
  • Each value separated by a comma
// Array of IPv4 address objects
{
  "addresses": [
    { "ip": "172.16.0.2", "netmask": "255.255.255.0" },
    { "ip": "172.16.0.3", "netmask": "255.255.255.0" },
    { "ip": "172.16.0.4", "netmask": "255.255.255.0" }
  ]
}
14.3

APIs

🔌
API (Application Programming Interface): Software that lets one application access another application's data or services. It's a set of rules describing how apps interact, plus instructions to make that interaction happen. User sends → API request → server responds with → API response + data.
🍽️
Analogy: API = waiter in a restaurant. Customer (user) → waiter (API) → kitchen (server/data) → waiter → customer. The API call is the message from the requesting application to the server where data lives.

🌐 Open / Public APIs

  • Publicly available, no restrictions
  • Often require a free key/token to control usage
  • Controls the number of requests processed

🔒 Internal / Private APIs

  • Used within an organization only
  • Not exposed publicly
  • Example: salespeople accessing internal sales data on mobile

🤝 Partner APIs

  • Used between a company and its business partners/contractors
  • Requires a license or permission
  • Example: travel site using an airline's API

🌍 Types of Web Service APIs

A web service = a service available over the internet via WWW. Four types:

Type Full Name Data Format Released Strength
SOAP Simple Object Access Protocol XML 1998 Well-established
REST Representational State Transfer JSON XML YAML 2000 Flexible, most widely used
XML-RPC XML Remote Procedure Call XML 1998 Well-established, simplicity
JSON-RPC JSON Remote Procedure Call JSON 2005 Simplicity
14.4

REST

🔄
REST API = an API that works on top of HTTP. It defines functions (GET, POST, etc.) for performing requests and receiving responses. "Conforming to REST constraints" = being RESTful.

✅ RESTful Constraints (must have ALL three)

Client-Server

Client handles front end, server handles back end. Either can be replaced independently.

Stateless

No client data stored on server between requests. Session state stored on the client.

Cacheable

Clients can cache server responses to improve performance.

⚡ HTTP Methods → CRUD Operations

HTTP MethodRESTful OperationWhat it does
POST Create Create a new resource on the server
GET Read Retrieve / read data from the server
PUT / PATCH Update Update an existing resource
DELETE Delete Remove a resource from the server

🔗 URI vs URN vs URL

  • URI (Uniform Resource Identifier) — string that identifies a specific network resource. Parent term.
  • URN (Uniform Resource Name) — identifies the namespace of the resource only; no protocol reference
  • URL (Uniform Resource Locator) — defines the network location of a resource; includes a protocol (HTTP, HTTPS, FTP, SFTP, SSH...)
// Example URI breakdown:
https://www.example.com/author/book.html#page155
│       │                │               │
Protocol Hostname          Path/File       Fragment

🏗️ RESTful Web Service — 4 Required Aspects

  • A base URI for the web service (e.g. http://example.com/resources)
  • A supported data format (JSON, YAML, XML, or any valid hypertext standard)
  • A set of HTTP methods supported (POST, GET, PUT/PATCH, DELETE)
  • The API must be hypertext driven

🧩 Anatomy of a RESTful Request

Example: MapQuest Directions API

http://www.mapquestapi.com/directions/v2/route?outFormat=json&key=KEY&from=San+Jose,Ca&to=Monterey,Ca
│                        │                   │                  │    │                 │
API Server               Resources           Format             Key  Parameter1        Parameter2
  • API Server — URL of the server answering REST requests
  • Resources — the specific API being requested (e.g. directions)
  • Query — specifies data format + info the client is requesting
  • Format — usually JSON, can be YAML or XML
  • Key — for authorization (if required by the API provider)
  • Parameters — specific info for the request (e.g. from/to locations)

🔑 Why API Providers Require a Key

  • Authenticate the source / verify authorization
  • Limit number of people using the API
  • Limit requests per user
  • Capture and track requested data
  • Gather info on people using the API

🛠️ Ways to Call a RESTful API

  • Web Browser — type the URI directly (works for simple GET requests)
  • Developer Web Site — API docs with interactive request builder
  • Postman — app for testing/using REST APIs; full support for query params and keys
  • Python — call APIs from within a script → enables automation, customization, app integration
  • Network Operating Systems — protocols like NETCONF and RESTCONF provide alternative methods for configuration, monitoring, and management
14.5

Configuration Management Tools

📟 Traditional Network Configuration (the old way)

  • Network admin configures devices one by one using the CLI
  • Every change/new feature must be manually entered on every device
  • Scales poorly — becomes a major issue on large/complex networks
  • SNMP — lets admins manage nodes on an IP network via a Network Management Station (NMS): monitor performance, find problems, query stats. NOT typically used for configuration due to security concerns and implementation difficulty
🚀
Network Automation: The shift from managing dozens of devices via CLI to deploying/managing thousands of physical and virtual devices with software. Tools include: REST, Ansible, Puppet, Chef, SaltStack, Python, JSON, XML, NETCONF.

⚙️ What Configuration Management Tools Do

Use RESTful API requests to automate tasks, scalable to thousands of devices. Aspects admins automate:

  • Software and version control
  • Device attributes: names, addressing, security
  • Protocol configurations
  • ACL configurations
📌
Automation = a tool automatically performs a task on a system.
Orchestration = arranging automated tasks to produce a coordinated process or workflow.

📊 Ansible vs Chef vs Puppet vs SaltStack

All support JSON and YAML. All come with RESTful API documentation.

Characteristic Ansible Chef Puppet SaltStack
Programming Language Python + YAML Ruby Ruby Python
Agent Model Agentless Agent-based Supports both Supports both
Controller / Master Any device can be controller Chef Master Puppet Master Salt Master
What tool creates Playbook Cookbook Manifest Pillar
🎯
Goal of all config tools: Reduce complexity and time involved in configuring/maintaining large-scale infrastructure with hundreds or thousands of devices. Also beneficial for smaller networks.

IBN & Cisco DNA Center

🌐
IBN (Intent-Based Networking) = the next-generation networking model. Builds on SDN. Transforms hardware-centric, manual network design to software-centric, fully automated. Business objectives are expressed as intent; IBN uses analytics, ML, and automation to keep the network aligned as business needs change.

🔺 Cisco IBN — Three Essential Functions

🗣️ Translation
→
⚡ Activation
→
✅ Assurance
Translation

Enables the admin to express expected networking behavior that supports the business intent.

Activation

Interprets captured intent into policies → installs them into physical/virtual infrastructure via networkwide automation.

Assurance

Maintains a continuous validation-and-verification loop to ensure expressed intent is honored at any point in time.

🔲 Overlay Network (Logical)

  • From IBN's view, network infrastructure is a fabric
  • Overlay = logical topology used to virtually connect devices
  • Limits the number of devices the admin must program
  • Provides services and forwarding methods not controlled by physical devices
  • Where encapsulation protocols like IPsec and CAPWAP occur
  • Physical connections between switches are not a concern of the overlay
  • Admin uses policies to control the overlay control plane

🔩 Underlay Network (Physical)

  • The physical topology including all hardware to meet business objectives
  • Reveals additional devices and how they are connected
  • End points (servers) access network through Layer 2 devices
  • Underlay control plane is responsible for simple forwarding tasks
  • Routing devices are Layer 3

🧬 Cisco DNA (Digital Network Architecture)

Cisco's implementation of the IBN fabric. Business intent is securely deployed into the fabric. Cisco DNA continuously gathers data from devices/applications to provide rich context, then analyzes it to ensure the network performs securely at optimal level in accordance with business intent and policies.

DNA SolutionDescriptionBenefits
SD-Access First intent-based enterprise networking solution built on Cisco DNA. Single network fabric across LAN and WLAN for consistent, secure user experience. Segments user/device/application traffic, automates user-access policies. Network access in minutes for any user/device/application without compromising security.
SD-WAN Cloud-delivered architecture that centrally manages WAN connections. Simplifies/accelerates delivery of secure WAN services across data centers, branches, campuses, colocation. Better app user experience. Greater agility and cost savings through easier deployment and transport independence.
DNA Assurance Troubleshoots and boosts IT productivity. Uses advanced analytics and ML to improve performance, predict and assure network performance, provides real-time notifications. Identify root causes, suggested remediation. Single dashboard with drilldown. ML predicts problems before they occur.
DNA Security Uses the network as a sensor for real-time analysis. Provides granular control to enforce policy and contain threats, even in encrypted traffic. Reduced risk, 360° visibility through real-time analytics, lower complexity with end-to-end security.

🖥️ Cisco DNA Center

The foundational controller and analytics platform at the heart of Cisco DNA. A hardware and software platform providing a "single-pane-of-glass" (single interface) focused on assurance, analytics, and automation. Used for provisioning and configuring network devices.

Launch page shows overall health summary and network snapshot. Five main menu areas:
