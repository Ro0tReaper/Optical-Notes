10.1 Device Discovery with CDP Cisco Only
CDP (Cisco Discovery Protocol) is a Cisco-proprietary Layer 2 protocol. It auto-discovers directly connected Cisco devices and reveals their type, name, and interface info — without needing IP connectivity.
  • Media and protocol independent — works on routers, switches, access servers
  • Sends periodic advertisements to directly connected neighbors only (not routed)
  • Enabled by default on all Cisco devices
  • Useful for mapping unknown network topology

Key Commands

  • show cdp — verify CDP is running
  • show cdp interface — show CDP-enabled interfaces
  • show cdp neighbors — list neighbors
  • show cdp neighbors detail — includes IP addresses

Enable / Disable

  • cdp run — enable globally
  • no cdp run — disable globally
  • cdp enable — enable on interface
  • no cdp enable — disable on interface
R1# show cdp neighbors Device ID Local Intrfce Holdtme Capability Platform Port ID S1 Gig 0/0/1 179 S I WS-C3560- Fas 0/5 R1# show cdp neighbors detail Device ID: S1 → IP address: 192.168.1.2
Use show cdp neighbors detail to find the IP address of a neighbor when you only know the physical connection.
10.2 Device Discovery with LLDP Vendor-Neutral
LLDP (Link Layer Discovery Protocol) is the open-standard (IEEE 802.1AB) equivalent of CDP. Works with any vendor's devices including routers, switches, and wireless APs.
  • Vendor-neutral — not Cisco specific
  • Also Layer 2, also sends neighbor advertisements
  • May or may not be enabled by default — must be configured separately to transmit and receive
Switch(config)# lldp run ← enable globally Switch(config-if)# lldp transmit ← per interface Switch(config-if)# lldp receive S1# show lldp neighbors ← basic neighbor list S1# show lldp neighbors detail ← includes IOS version + IP

CDP vs LLDP

  • CDP = Cisco only
  • LLDP = any vendor
  • Both are Layer 2
  • Both use similar show commands

LLDP Extra Detail

  • Shows IOS version
  • Shows IP address
  • Shows device capabilities
  • TX and RX configured separately
10.3 NTP — Network Time Protocol UDP 123
NTP synchronizes clocks across all network devices. Consistent time is critical for log correlation and event ordering. Uses UDP port 123, documented in RFC 1305.
  • Router software clock starts at boot — not reliable without NTP
  • Manual config: clock set 20:36:00 nov 15 2019 — only works for small networks
  • NTP uses a hierarchical stratum system — stratum = hops from authoritative source
  • Max stratum = 15. Stratum 16 = unsynchronized
StratumWhat it is
0Atomic clock / GPS — the actual time source (not on network)
1Directly connected to stratum 0 — primary NTP server
2Syncs from stratum 1 — can also serve stratum 3 clients
3+Each hop adds 1 to the stratum number
16Unsynchronized — ignore this device for time
-- Configure R1 to sync from NTP server -- R1(config)# ntp server 209.165.200.225 -- Verify -- R1# show clock detail ← should say "Time source is NTP" R1# show ntp associations ← shows NTP server + ref clock + stratum R1# show ntp status ← shows stratum level of this device -- Configure S1 to sync from R1 -- S1(config)# ntp server 192.168.1.1 ← R1's IP → S1 becomes stratum 3
If R1 syncs from a stratum 1 server, R1 becomes stratum 2. S1 syncing from R1 becomes stratum 3. Each hop = +1.
10.4 SNMP — Simple Network Management Protocol UDP 161/162
SNMP lets network admins monitor and manage devices remotely. Manager polls agents on UDP 161. Agents send traps to manager on UDP 162.

Three Components

  • SNMP Manager — the NMS, runs get/set
  • SNMP Agent — runs on managed device
  • MIB — database of variables on device

Manager Operations

  • get — read a variable from MIB
  • set — write/change a variable
  • trap — agent pushes alert to manager (unsolicited)
OperationDescription
get-requestGet value of one specific variable
get-next-requestSequential search through a table
get-bulk-requestGet large blocks at once (SNMPv2+)
get-responseAgent reply to any get/set request
set-requestWrite a value to a variable

SNMP Versions:

VersionAuth MethodSecurity
SNMPv1Community string (plaintext)Weak — avoid
SNMPv2cCommunity string (plaintext)Adds bulk ops + better errors. Often used read-only
SNMPv3Username + HMAC-MD5/SHAEncryption (DES/3DES/AES) — use this

Community Strings (v1/v2c) — act as plaintext passwords for MIB access:

  • ro (read-only) — can read MIB variables, cannot change them
  • rw (read-write) — full read/write access to MIB

MIB Object IDs (OIDs) — unique identifiers in a hierarchical tree:

Cisco OID path: iso(1) → org(3) → dod(6) → internet(1) → private(4) → enterprises(1) → cisco(9) Result: OID = 1.3.6.1.4.1.9 Polling example (snmpget tool): snmpget -v2c -c community 10.250.250.14 .1.3.6.1.4.1.9.2.1.58.0 Returns: INTEGER: 11 ← CPU value
Traps are unsolicited — the agent notifies the manager when something happens (e.g. interface down), reducing polling overhead.
10.5 Syslog UDP 514
Syslog is the standard logging protocol. Devices send event messages to a syslog server (or local buffer/console) over UDP port 514. Critical for monitoring and troubleshooting.

Syslog message destinations:

  • Logging buffer — RAM inside router/switch, view with CLI
  • Console line — shown on console session
  • Terminal line — shown on VTY (SSH/Telnet) session
  • Syslog server — centralized external server (preferred)

Severity Levels — lower number = more critical:

LevelNameMeaning
0EmergencySystem unusable
1AlertImmediate action needed
2CriticalCritical condition
3ErrorError condition
4WarningWarning condition
5NotificationNormal but significant
6InformationalInfo message
7DebuggingDebug output

Message format:

%FACILITY-SEVERITY-MNEMONIC: description Example: %LINK-3-UPDOWN: Interface Port-channel1, changed state to up ↑FACILITY ↑SEV ↑MNEMONIC

Common Facilities: IP, OSPF, SYS, IPsec, IF (Interface IP)

Timestamps (not enabled by default):

R1(config)# service timestamps log datetime After this, messages include: *Mar 1 11:52:42: %LINK-3-UPDOWN: ...
Always enable timestamps before sending logs to a syslog server, otherwise you lose track of when events happened.
10.6 Router & Switch File Maintenance Config Backup

Cisco IOS File System (IFS) — navigate with familiar commands:

Router# show file systems ← list all filesystems (* = default, # = bootable) Router# dir ← list flash contents (default filesystem) Router# cd nvram: ← change to NVRAM Router# pwd ← show current directory Router# dir ← now lists NVRAM (startup-config is here)

Backup Methods

  • Tera Term → File → Log → show running-config
  • TFTP: copy running-config tftp
  • USB: copy run usbflash0:/

Restore Methods

  • Tera Term → File → Send File
  • TFTP: copy tftp running-config
  • USB: copy usbflash0:/R1-Config running-config
-- TFTP Backup -- R1# copy running-config tftp Remote host []? 192.168.10.254 Name of the configuration file? R1-Jan-2019

Password Recovery Procedure

  1. Enter ROMMON mode — use break sequence during boot or remove flash while powered off. Prompt shows rommon 1 >
  2. Change config register: confreg 0x2142 then reset — this makes the device ignore startup-config on next boot
  3. Copy startup to running: copy startup-config running-config — loads old config without booting from it
  4. Change the password: enable secret <newpassword>
  5. Restore register & save: config-register 0x2102 then copy running-config startup-config
  6. Reload the device: reload
Never run copy running-config startup-config BEFORE copying startup to running in step 3 — you'll erase the original config.
10.7 IOS Image Management TFTP / Flash
Store IOS images on a TFTP server as backup. If flash gets corrupted or erased, you can restore the image from TFTP over the network.

Backup IOS to TFTP:

  1. Ping TFTP server to verify connectivity
  2. Check image size: show flash0: — ensure TFTP has enough space
  3. Copy: copy source-url destination-url — you'll be prompted for filename and IP

Restore IOS from TFTP:

  1. Ping TFTP server to verify connectivity
  2. Check free flash: show flash: — ensure space for new image
  3. Copy image: copy tftp: flash: — enter server IP, source filename, destination
R1# copy tftp: flash: Address or name of remote host []? 2001:DB8:CAFE:100::99 Source filename []? isr4200-universalk9_ias.16.09.04.SPA.bin Destination filename? [same] Loading... 517153193 bytes copied in 868.128 secs

boot system — tell the router which IOS image to load:

R1(config)# boot system flash0:isr4200-universalk9_ias.16.09.04.SPA.bin R1(config)# exit R1# copy running-config startup-config R1# reload
If no boot system command exists, the router loads the first valid IOS image found in flash by default.
