01 What is the Control Layer?
The middle layer — sits between service requests and physical hardware

The control layer receives requests from the service layer (e.g. "give me a VM with 4 GB RAM and 80 GB HDD") and talks to the virtual and physical layers to actually make it happen.

Three core functions

Configuration

Set up and modify infrastructure components (OS install, VLANs, RAID, zoning, LUN masking, etc.)

Provisioning

Allocate resources from pools and hand them to service instances on demand.

Monitoring

Track performance, availability, capacity, and security across all infrastructure.

To allocate resources, they must first be pooled and managed centrally. Control software works together with virtualization software to enable resource pooling, dynamic allocation, and utilization optimization.

Two types of control software

Element Manager

Manages one specific type of infrastructure component (compute, network, or storage) through that component's own API.

Unified Manager

Single pane of glass — manages all infrastructure types through one interface by talking to each element manager's API.

02 Element Manager
Per-component management — one manager per infrastructure type

Vendors ship element managers either built into the hardware or as external software. There are three kinds: Compute System Management Tool, Fabric Management Tool (network), and Storage System Management Tool. Each talks to its hardware via its own API.

What an element manager can do
  • Initial & ongoing configuration — install guest OS, configure zoning, security settings, VLANs, RAID levels, LUN masking.
  • Capacity expansion — detects newly added hardware and adds it to an existing resource pool automatically.
  • Troubleshooting — identify faults and diagnose problems in the component it manages.
  • Monitoring — tracks performance, availability, capacity, and security of that specific component.
Think of it as the dedicated manager for one domain: the storage element manager only knows about storage; the compute element manager only knows about compute, etc.
03 Unified Manager
One management interface to rule them all

The Unified Manager sits on top of all the element managers. It communicates with each element manager (and directly with infrastructure) through their native APIs, giving administrators a single consolidated view of all resources — compute, network, and storage — wherever they live.

Key capabilities
  • Discovers and collects configuration, connectivity, and utilization info from all cloud infrastructure elements.
  • Compiles this into one consolidated view.
  • Exposes APIs so administrators can integrate it with other tools (automation, billing, orchestration).
  • Used to both manage resources and provision them for services.

04 Resource Discovery
Figuring out what resources exist before you can use them

Discovery is the process of learning what resources are available for cloud service deployment. It can run on a schedule (periodic intervals set by the admin) or be triggered manually when a change occurs in the infrastructure.

Compute discovery

  • Number of blade servers
  • CPU speed
  • Memory capacity
  • Virtual-to-physical compute mapping

Network discovery

  • Switch model
  • Network adapters
  • VLAN IDs / VSAN IDs
  • Physical-to-virtual network mapping
  • QoS, topology, zones

Storage discovery

  • Storage system type
  • Drive type
  • Total / free / used capacity
  • RAID level
  • Storage pools
  • Physical-to-virtual storage mapping
05 Resource Management — Pools
Aggregating and organizing physical resources into pools

Once discovered, physical resources are grouped into resource pools. Virtual resources (VMs, virtual volumes, virtual networks) are created from these pools and provisioned to services. The control software also lets you grade these pools.

Resource Grading = categorizing pools by performance, capacity, and availability so you can offer different service tiers to consumers.
06 Resource Grading — Gold / Silver / Bronze
Tiered pools = tiered service offerings

Pools of different grades let the provider offer a variety of service levels. Grade levels can be defined for compute (CPU + memory), storage, and network (WWN, VLAN ID) pools. The number of grades depends on business requirements.

Storage grading example (the one used in the lecture)

Gold

  • Drives: Flash + FC + SATA
  • Supports automated storage tiering
  • Total: 3 TB (Flash 1TB, FC 1TB, SATA 1TB)
  • RAID level 5

Silver

  • Drives: Flash + FC + SATA
  • Supports automated storage tiering
  • Total: 3 TB (Flash 0.5TB, FC 1TB, SATA 1.5TB)
  • RAID level 1+0

Bronze

  • Drives: FC only
  • No automated storage tiering
  • Total: 2 TB
  • RAID level 5
07 Resource Allocation Models
Two ways to control how much a service instance gets

Relative Resource Allocation

Resources are assigned proportionally relative to other service instances. No fixed amounts — it's about ratios.

Example: Platinum = 2X priority, Gold = X priority. Under contention, Platinum gets twice as much as Gold.

Absolute Resource Allocation

Resources are assigned as hard numbers with a lower bound (minimum guaranteed) and upper bound (maximum allowed).

Example: VM has lower bound 2 GB / 1200 MHz, upper bound 4 GB / 2400 MHz.

Absolute allocation — exam-favourite scenario
  • If available resources < lower bound → the VM will NOT power on.
  • If available resources > upper bound → VM is still capped at the upper bound (4 GB / 2400 MHz). It cannot consume more than the maximum even if more is free.
  • Normal operation → VM runs between the lower and upper bounds based on what it needs and what's available.
08 Compute Resource Management
Techniques to get the most out of physical CPUs and memory

Hyperthreading

Each physical CPU core presents itself as two logical cores. A dual-core CPU appears as 4 logical cores. VMs get virtual processors mapped to these logical cores. More VMs can be packed onto one physical host.

Memory Page Sharing

If multiple VMs have identical memory pages (e.g. same OS), the hypervisor maps them all to one physical copy. Only when a VM modifies the page does it get its own private copy (copy-on-write). Reduces actual physical RAM usage.

Dynamic Memory Allocation

Memory is not statically assigned to VMs. The hypervisor expands or shrinks a VM's memory allocation at runtime based on demand, so unused memory from idle VMs can be given to busy ones.

VM Load Balancing

The control software monitors host utilization and migrates VMs between physical servers (live migration) to balance workload and prevent hotspots.

Server Flash Caching

Install SSD/flash storage inside the server as a fast local cache. Frequently accessed data is served from flash instead of going to the SAN, dramatically reducing I/O latency for that server's VMs.

09 Storage Resource Management
Managing how storage is carved up and tiered

Thick vs. Thin Provisioning

  • Thick: All storage space is allocated upfront. The full amount is reserved even if unused. Predictable, no risk of running out mid-operation.
  • Thin: Only the space actually used is consumed. Can over-provision (promise more than physically exists). More flexible but requires monitoring.

Storage Pool Rebalancing

As data is added/removed over time, some drives in a pool get more loaded than others. Rebalancing redistributes data evenly across all drives to maintain performance.

Automated Storage Tiering

Automatically moves frequently accessed ("hot") data to faster drives (Flash/SSD) and cold data to slower drives (SATA) — without manual intervention. Optimizes cost vs. performance.

Cache Tiering

Adds a cache tier inside the storage system itself: Tier 0 = DRAM cache (fastest), Tier 1 = SSD. Hot data lives in cache; cold data sits on spinning disk. Reduces latency for active workloads.

10 Network Resource Management
Controlling and optimizing network bandwidth usage

Limit and Share

Set maximum bandwidth a VM or tenant can use (limit) and define proportional shares when there's contention (share). Similar to the relative/absolute allocation models applied to bandwidth.

Traffic Shaping

Enforces a rate limit at a network port. If traffic exceeds the limit, excess packets are queued (not dropped) for later transmission — unlike policing which drops them. Ensures SLA for critical apps and prevents one tenant from flooding the network.

Link Aggregation

Bundles multiple physical links between switches (or switch-to-server) into one logical link. Distributes traffic across all links. Covered in depth in Week 11.

NIC Teaming

Server-side version of link aggregation. Multiple NICs combined into one logical interface. Provides both load balancing across NICs and failover if one NIC or link fails.

Multipathing

Multiple physical paths exist between a server and its storage or network. Multipathing software uses all of them simultaneously for load balancing and automatically reroutes traffic if a path fails, improving I/O performance and path utilization.

11 Resource Provisioning
The final step — actually delivering resources to the customer

Provisioning = allocating resources from graded resource pools to service instances. It's the end-to-end fulfillment of a customer's request.

How it works (two-step)
1. Consumer picks a service from the service catalog
→
2. Control software allocates resources from the right graded pool and wires everything together per the service template
→
Service instance is live
The service template defines what the service looks like — which compute grade, which storage grade, which network config. Provisioning instantiates that template with real resources from the pools.
