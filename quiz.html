Q16 Reasoning
Explain the difference between a WWN and an FC address, including why both are needed.
Answer: WWN (World Wide Name) is a static, permanent 64-bit identifier burned into hardware (like a MAC address). It identifies the adapter (WWNN) or each port on that adapter (WWPN). FC address is a dynamic 24-bit address assigned when a node logs into the fabric via FLOGI. Both are needed because: WWN provides permanent identity for zoning and LUN masking (survives fabric changes), while FC address enables efficient routing within the fabric (changes based on where the node connects). The Name Server maintains the live mapping between WWN and FC address.
Q17 Reasoning
A dual-port FC HBA has how many WWNNs and WWPNs? Explain why.
Answer: A dual-port FC HBA has 1 WWNN (World Wide Node Name) and 2 WWPNs (World Wide Port Names). The WWNN identifies the adapter card itself (one physical piece of hardware). Each port on that adapter gets its own WWPN because each port is a separate communication endpoint that may connect to different fabrics or switches.
Q18 Reasoning
Why does multimode fiber have shorter distance limitations than single-mode fiber?
Answer: Multimode fiber (MMF) sends multiple light beams at different angles through the core. These beams travel different path lengths and arrive at slightly different times — a phenomenon called modal dispersion. The overlapping and collision of beams weakens the signal over distance. Single-mode fiber (SMF) sends a single ray of light through the center of a much smaller core, eliminating modal dispersion and allowing distances up to 10 km.
Q19 Reasoning
Describe the complete login sequence when a compute system connects to an FC SAN.
Answer: The sequence is: (1) FLOGI — node sends Fabric Login to FFFFFE with its WWNN and WWPN, receives FC address back. (2) Node registers with Name Server (FFFFFC). (3) Node queries Name Server for available targets. (4) PLOGI — node establishes session with a specific target, exchanging service parameters. (5) PRLI — FC-4 protocol-level login where nodes exchange SCSI-specific parameters. After PRLI completes, I/O can begin.
Q20 Reasoning
Explain the purpose of RSCNs and how zoning reduces their impact in large fabrics.
Answer: RSCNs (Registered State Change Notifications) are sent by the Fabric Controller when something changes in the name server database (e.g., a node joins or leaves). Without zoning, RSCNs go to every single node in the fabric — generating massive unnecessary management traffic in large fabrics. With zoning, RSCNs only go to nodes within the affected zone, significantly reducing management traffic. This is one of the key reasons zoning is essential in large FC fabrics.
Q21 Reasoning
What is link aggregation and how does it improve upon traditional ISL handling?
Answer: Link aggregation bundles two or more parallel ISLs into a single logical port-channel. Without link aggregation, traffic is assigned to ISLs in round-robin, causing some ISLs to become overloaded while others sit idle. With link aggregation, traffic for any node pair distributes across all ISLs in the port-channel, ensuring even utilization. Example: 10 ISLs × 16 Gb/s each = 160 Gb/s port-channel throughput with balanced load.
Q22 Reasoning
Compare the three FC interconnectivity options (Point-to-Point, FC-AL, FC-SW) in terms of scalability and performance.
Answer: Point-to-Point: Dedicated connection between two nodes only. Simple but no scalability — limited to DAS-like use. FC-AL (Arbitrated Loop): Devices share a loop, must arbitrate for access, only one transmits at a time. No switch needed but low performance, and adding/removing devices causes loop re-initialization (brief traffic pause). FC-SW (Switched Fabric): Nodes connect through switches with dedicated paths. Highest performance, highest scalability, adding/removing nodes minimally disruptive. Cost is switches required.
Q23 Reasoning
Explain what happens during BB_Credit flow control when credit reaches zero.
Answer: During port login, transmitter and receiver agree on a credit count (number of receive buffers). Each time a frame is sent, credit decrements by 1. When the receiver processes a frame and frees a buffer, it sends R_RDY back, incrementing the sender's credit by 1. If credit reaches 0, transmission is suspended — the sender cannot send more frames until R_RDY is received. This prevents frames from being dropped due to buffer overflow, making FC deterministic and reliable for storage traffic without requiring TCP-style retransmission.
Q24 Reasoning
What is bridged iSCSI and when would you use it?
Answer: Bridged iSCSI is used when compute systems are on an IP network but storage systems are on an FC SAN (without native iSCSI ports). A gateway device with both Ethernet and FC ports bridges the two worlds. The initiator targets the gateway's IP address, and the gateway converts IP packets ↔ FC frames. The gateway acts as an FC initiator toward the storage system. Use it when you have existing FC storage that needs to serve IP-based clients without replacing the storage system.
Q25 Reasoning
Explain the three parts of an IQN (iSCSI Qualified Name) format.
Answer: IQN format: iqn.YYYY-MM.reverse-domain:optional_string. The three parts are: (1) "iqn." prefix — identifies this as an IQN format name. (2) Date (year-month) — prevents conflicts when domain ownership changes hands; based on when the domain was registered. (3) Reversed registered domain name — ensures global uniqueness, followed by an optional string (serial number, asset tag, etc.) for additional uniqueness within the organization. Example: iqn.2015-04.com.example:server01.
Q26 Reasoning
Why does FCIP potentially cause IP packet fragmentation, and how is this handled?
Answer: FC frames can be large (up to 2,112 bytes payload). When encapsulated inside an IP packet with additional headers, the resulting packet may exceed the MTU (Maximum Transmission Unit) of the underlying data link (typically 1500 bytes for Ethernet). This causes IP packet fragmentation into smaller pieces. TCP handles receiving and re-sequencing these fragments before passing the reconstructed data to the FC processing layer. This fragmentation is a known overhead of FCIP.
Q27 Reasoning
Compare the advantages of Port Zoning versus WWN Zoning when an HBA fails and is replaced.
Answer: When an HBA fails and is replaced: Port Zoning requires no reconfiguration because the zone is based on the switch port ID, which stays the same. The new HBA simply plugs into the same port and inherits the existing zone membership. WWN Zoning requires updating the zone configuration because the new HBA has a different WWN than the failed one. The old WWN must be removed and the new WWN added to the zone. This is why some environments prefer Port Zoning for operational simplicity in hardware replacement scenarios.
Q28 Reasoning
What is the structure of an FC frame, and what is the purpose of the CRC field?
Answer: An FC frame consists of 5 parts: SOF (Start of Frame delimiter), Frame Header (24 bytes containing addressing info like source/destination/sequence ID), Data Field (up to 2,112 bytes of actual payload, usually SCSI data), CRC (Cyclic Redundancy Check), and EOF (End of Frame delimiter). The CRC is calculated by the sender before FC-1 encoding and verified by the receiver after decoding. Its purpose is error detection — ensuring the frame arrived intact without corruption during transmission.
Q29 Reasoning
Explain the relationship between Exchange, Sequence, and Frame in FC data transport.
Answer: These form a hierarchical structure: An Exchange is a complete operation between two ports (e.g., a full read or write I/O). Each Exchange is composed of one or more Sequences. A Sequence is a contiguous set of frames from one port to another, corresponding to one Information Unit (IU) as defined by the Upper Layer Protocol. Each Sequence is composed of one or more Frames, which are the fundamental unit of data transfer at FC-2. Think of it as: Frame = single word, Sequence = sentence, Exchange = full conversation.
Q30 Reasoning
Compare FC-SAN, iSCSI, and FCIP in terms of transport protocol, distance limitation, and primary use case.
Answer: FC-SAN: Transport = Fibre Channel (FCP). Distance = Limited (~10 km max with SMF). Use = Primary SAN fabric within data centers. iSCSI: Transport = TCP/IP over Ethernet. Distance = None (IP has no inherent limit). Use = IP-based block storage access, replacing or supplementing FC. FCIP: Transport = FC frames tunneled over TCP/IP. Distance = None (IP). Use = Connecting distant FC SANs over IP for disaster recovery and data replication. FCIP doesn't replace FC — it extends it over IP networks.

Q16Reasoning
Explain why scatter-gather traffic pattern is the dominant driver for data center network redesign.
Answer: Scatter-gather creates intense, simultaneous bursts of traffic flowing in many directions at once between servers across different racks — called east-west traffic. Traditional networks were designed for north-south (client-to-server) traffic with limited internal bandwidth. Cloud applications (search, recommendation, distributed computation) all use scatter-gather, generating enormous internal traffic for every user request. This mismatch between traffic pattern and network design drove all topology innovations (ToR, Clos) to handle massive east-west bursts efficiently.
Q17Reasoning
Compare ToR and EoR layouts with at least 3 advantages and 3 disadvantages of each.
Answer: ToR Pros: Copper stays in-rack (short), lower cabling costs, cleaner management, modular per-rack, excellent east-west support, easier per-rack speed migration. ToR Cons: More switches to manage, higher switch costs/power, more aggregation ports needed, more STP instances. EoR Pros: Fewer switches to manage, lower switch/maintenance costs, fewer aggregation ports, accommodates mixed speeds. EoR Cons: Expensive long copper runs (10-30m), cable management nightmare, more patching infrastructure, limits high-speed I/O adoption (long copper can't support 25G/100G).
Q18Reasoning
Explain how a Clos network provides multiple equal-cost paths between any two servers.
Answer: A Clos has three tiers: server access (ToR) → aggregation (per pod) → multiple core switches. Each aggregation switch connects to all ToRs in its pod AND to all core switches. Each core switch connects to one aggregation switch in every pod. This means traffic from Pod 0 to Pod 2 can take multiple routes through different core switches — all with equal cost. ECMP (Equal-Cost Multi-Path) distributes flows across all available paths using hash-based load balancing.
Q19Reasoning
What are the "mice and elephants" in data center flow sizes, and why is this a problem?
Answer: "Mice" are the vast majority of flows — tiny and short-lived (Facebook Hadoop median <1KB, >80% of flows last <10sec). "Elephants" are a small number of large flows carrying disproportionate data. This mix creates challenges: treating both the same means elephants block mice; prioritizing differently needs complex management. Network design must handle both simultaneously — small latency-sensitive flows AND large bandwidth-hungry flows — without them interfering.

Q22Reasoning
What is the 10:1 oversubscription problem in the Google Jupiter example?

If one fails, others continue — no single point of failure like a monolithic core switch.

What is "full bisection bandwidth" and why is it important in Clos networks?
Answer: Full bisection bandwidth means the bandwidth available when you cut the network in half equals the total bandwidth of all servers on one side. In a Clos, this means no oversubscription — any server can communicate with any other server at full line rate simultaneously. This is important because it eliminates congestion regardless of traffic pattern. Traditional topologies have oversubscribed uplinks, forcing traffic to stay local. Clos with full bisection allows any-to-any communication without bandwidth constraints.
Q28Reasoning
Explain what ECMP is and how it works in a Clos network.
Answer: ECMP (Equal-Cost Multi-Path) distributes traffic across all available paths of equal cost. It works by hashing header fields (src IP, dst IP, src port, dst port) to produce a number that selects which path the flow takes. All packets in the same flow always take the same path, preserving packet order. In a Clos network with multiple core switches, ECMP spreads flows across all cores automatically — no manual configuration needed. This provides both load balancing and fault tolerance (if one path fails, others continue).
