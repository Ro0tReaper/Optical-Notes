R3Easy
What are the three FC interconnectivity options and what is the key difference between FC-AL and FC-SW?

✓ Model Answer

Three options: (1) Point-to-Point—Two nodes connected directly, no scalability; (2) FC-AL (Arbitrated Loop)—Devices share a loop, must arbitrate for access, only one transmits at a time, adding/removing devices causes loop re-initialization; (3) FC-SW (Switched Fabric)—Nodes connect through switches, dedicated path between any two nodes, adding/removing nodes is minimally disruptive. Key difference: FC-AL shares the loop (one device transmits at a time, low performance), while FC-SW provides dedicated paths (high performance, high scalability).

R4Medium
Explain the five layers of the FC protocol stack (FC-0 to FC-4) and what each layer does. Why is FC-3 skipped in practice?

✓ Model Answer

FC-4 (Protocol Mappings): Maps Upper Layer Protocols like SCSI to FC—where SCSI commands live. FC-3: Originally reserved for common services—skipped in practice (not implemented). FC-2 (Framing & Signaling): FC addressing, frame structure (frames/sequences/exchanges), fabric services, classes of service, flow control, routing. FC-1 (Encoding/Decoding): Encodes 8-bit to 10-bit (or 64-bit to 66-bit for 10 Gbps+), defines frame delimiters, primitive signals, link initialization, error recovery. FC-0 (Physical Interface): Cables, connectors, optical/electrical specs, bit transmission. FC-3 was originally reserved for common services but was never implemented in practice.

This analogy explains the difference between FC address and WWN. FC address is like your seat number at a restaurant—it changes each visit (dynamic, assigned when logging into fabric). WWN is like your national ID number—it's permanent and always yours (static, 64-bit globally unique identifier burned into hardware). R6Medium
Explain the relationship between frames, sequences, and exchanges in FC data transport using the conversation analogy from the summary.

✓ Model Answer

Using the conversation analogy: A frame = a single word (fundamental unit of data transfer at FC-2). A sequence = a sentence (a contiguous set of frames from one port to another, corresponds to one Information Unit). An exchange = a full conversation (a complete operation between two ports, composed of one or more sequences). For example, a full read I/O operation is an exchange containing multiple sequences (command, data transfer, status), each sequence containing multiple frames carrying the actual data.

R7Medium
List the four Fabric Services, their FC addresses, and their functions. Which service distributes RSCNs?

✓ Model Answer

Four Fabric Services: (1) Fabric Login Server (FFFFFE)—Assigns FC addresses during FLOGI; (2) Name Server (FFFFFC)—Registers and manages all logged-in node ports, maps WWNs to FC addresses, distributed across switches; (3) Fabric Controller (FFFFFD)—Manages and distributes RSCNs (Registered State Change Notifications), generates SW-RSCNs between switches; (4) Management Server (FFFFFA)—Lets SAN management software retrieve information and administer the fabric. The Fabric Controller (FFFFFD) is the service that distributes RSCNs.

R8Medium
Explain the "loading dock" analogy for BB_Credit flow control. What happens when credit is zero, and how does it recover?

✓ Model Answer

The analogy: A warehouse loading dock has 5 parking bays (receive buffers). Each truck (frame) arriving parks in a bay (credit decrements by 1). When the truck unloads and leaves, the dock sends a "bay free" signal (R_RDY) back to the sender (credit increments by 1). When credit = 0 (all bays full), transmission is suspended—the sender holds frames until a bay opens (R_RDY received). This prevents trucks from crashing into a full dock (no dropped frames). Recovery: Receiver processes frame, frees buffer, sends R_RDY, sender's credit increments, transmission resumes.

R9Medium
Compare single-switch, full mesh, partial mesh, and core-edge topologies. What are the main pros and cons of each?

✓ Model Answer

Single-Switch: Pros—No ISLs needed, all ports available, zero ISL delays; Cons—Limited by port count of one switch, not infinitely scalable. Full Mesh: Pros—Max 1 ISL hop, low latency; Cons—ISL port count grows rapidly, best for ≤4 switches. Partial Mesh: Pros—More scalable than full mesh; Cons—Multiple hops possible, ISL overload risk. Core-Edge: Pros—Scales well, compute-to-storage crosses only 1 ISL, conserves ports, easy expansion; Cons—More complex design, core must be highly available. Core-Edge is the preferred topology for large data centers.

R10Hard
Explain link aggregation in FC. What problem does it solve, and provide the numerical example from the summary.

✓ Model Answer

Link aggregation bundles two or more parallel ISLs into a single logical ISL called a port-channel. Problem solved: Without link aggregation, traffic is assigned to ISLs in round-robin, causing some ISLs to become overloaded while others are idle. With link aggregation, traffic for any node pair distributes across all ISLs in the port-channel, ensuring even utilization. Numerical example from summary: 10 ISLs × 16 Gb/s each = 160 Gb/s port-channel throughput. Traffic distributes across all 10 links instead of one being congested.

R11Hard
Explain the "private rooms in an open-plan office" analogy for zoning. How does zoning reduce RSCN impact in large fabrics?

✓ Model Answer

Zoning analogy: Like creating private rooms in a large open-plan office. Only people in the same room can talk directly. Even though everyone is in the same building (same SAN fabric), a developer in Room A cannot see or talk to accounting data in Room B. The building manager (fabric controller) only sends building-wide announcements (RSCNs) to the rooms they actually affect. RSCN reduction: Without zoning, when anything changes in the fabric, the Fabric Controller sends RSCNs to every single node—lots of unnecessary management traffic. With zoning, RSCNs only go to nodes within the affected zone, significantly reducing management traffic in large fabrics.

R13Hard

✓ Model Answer

Standard NIC + Software iSCSI: CPU handles ALL TCP/IP processing AND SCSI encapsulation—Highest CPU load, Lowest cost. R14Hard
Explain the three iSCSI name formats (IQN, EUI, NAA). Why does IQN include a date, and what is NAA used for?

✓ Model Answer

IQN (iSCSI Qualified Name): Format iqn.YYYY-MM.reverse-domain:optional_string. The date prevents conflicts when domain changes ownership—ensures uniqueness even if domain is sold/transferred. Most common, admin-friendly. EUI (Extended Unique Identifier): Based on IEEE EUI-64 standard, prefix "eui.", 16 hex characters after prefix. NAA (Network Address Authority): Defined by INCITS T11 (same body as FC), prefix "naa.", up to 32 hex chars (128-bit). NAA is used for devices with both iSCSI and SAS ports—the same name works for both protocols.

R15Hard
Explain why FCIP can cause IP packet fragmentation and how this is handled. What causes this problem?

✓ Model Answer

FC frames can be large. When encapsulated inside an IP packet, the resulting IP packet may exceed the MTU (Maximum Transmission Unit) of the underlying data link (e.g., Ethernet). This causes the IP packet to be fragmented into smaller pieces to fit the MTU. Handling: TCP handles receiving and re-sequencing these fragments before passing the reconstructed data to the FC processing layer. This is a known overhead of FCIP—the fragmentation and reassembly process adds latency and processing burden.

DCTCP steps: (1) Buffer occupancy exceeds threshold K at switch; (2) Switch marks packets with CE (Congestion Experienced) bit; (3) Receiver reflects marks in ACKs back to sender; (4) Sender counts fraction of marked ACKs; (5) Sender reduces window proportionally to that fraction. "Proportional": If 33% marked → reduce by ~33% (not standard TCP's fixed 50%). If 10% marked → reduce by ~10%. Gentler, more precise reduction based on actual congestion level, keeps buffers small and latency low.

Compare OSPF and BGP as data center routing options. When would you use each?

✓ Model Answer

OSPF: Layer 3 link-state protocol, same advantages as TRILL (ECMP, flexible topology, traffic control). Well-established, widely understood. Disadvantages: Needs IP addresses and subnet config on every link (more overhead), broadcast traffic scales with topology size (noisy in large DCs). BGP: Divide groups into Autonomous Systems (ASes), use BGP between them. Highly scalable—used by hyperscalers (Facebook, Google) in their DCs. More complex config but handles massive scale. Use OSPF for smaller DCs where simplicity matters; BGP for massive scale where OSPF's broadcast overhead becomes problematic.

R11Hard
Explain the difference between leaf and spine switches in FabricPath.

✓ Model Answer

Leaf switch: Connects Classical Ethernet (CE) hosts to FabricPath fabric. Has both CE edge ports and FabricPath core ports. Must be STP root for its CE domain (priority 4096). If not root, ports go Root Inconsistent via RootGuard. Learns local MACs on CE ports, remote MACs conversationally. Spine switch: Pure backbone—all ports are FabricPath mode. No STP, no classical Ethernet. Routes frames between leaf switches using Switch IDs. Multiple spines provide ECMP paths. No MAC learning of CE hosts—only Switch ID forwarding.

R12Hard
Explain the FabricPath header fields: Switch ID, Subswitch ID, LID, TTL, FTag, U/L bit, I/G bit.

✓ Model Answer

FabricPath header: Switch ID (12-bit)—unique per switch, used for forwarding, populates MAC + FabricPath tables; Subswitch ID (3-bit)—identifies group of hosts within a switch; LID (6-bit)—Local ID, identifies specific destination/source interface; TTL (6-bit)—decremented at each hop, prevents loops; FTag (10-bit)—Forwarding Tag, identifies spanning tree for multicast/broadcast; U/L bit—set on all unicast frames, MAC addresses are locally significant; I/G bit—Individual (unicast) vs Group (multicast/broadcast) frame. Ethertype 0x8903 marks all FabricPath frames.

R13Hard
Why is IS-IS used as the control plane for both TRILL and FabricPath? What advantages does it have?

✓ Model Answer

IS-IS advantages: (1) Doesn't need IP addresses—uses its own L3 transport, works at L2 without IP config on every link; (2) Natively supports ECMP → enables L2 load balancing without STP, Port Channels, or vPC; (3) Link-state protocol → computes Shortest Path Trees between all nodes; (4) Well-proven, widely implemented. In TRILL: IS-IS routes L2 frames (not IP). In FabricPath: IS-IS computes SPTs between FabricPath nodes. IS-IS is NOT used for MAC address advertisement—only for switch-level topology in both protocols.

R14Hard
Compare TRILL and FabricPath. What is the same and what is different?

✓ Model Answer

Same: Both are L2MP implementations; both use IS-IS control plane; both provide ECMP; both eliminate STP blocking; both encapsulate frames (TRILL header vs FabricPath header); both use TTL/Hop Count for loop prevention. Different: TRILL is IEEE standard (interoperable), FabricPath is Cisco proprietary (not interoperable with TRILL); Different header formats (TRILL: Egress/Ingress Nicknames; FabricPath: Switch ID, LID, FTag); FabricPath has conversational MAC learning; FabricPath requires specific hardware (Nexus 7K F1/F3, Nexus 5500); Different multicast/broadcast distribution mechanisms.

R15Hard
Summarize the progression of techniques from STP to DCTCP. What problem does each solve and what limitation leads to the next?

✓ Model Answer

Progression: STP → prevents loops but blocks redundant links (wasted capacity). EtherChannel → fools STP for same-switch bundles, but limited to one switch. StackWise/vPC → extends to different switches, but limited to pairs/physical stacking. TRILL/FabricPath → replaces STP entirely, all links active, ECMP, but doesn't solve congestion control. OSPF/BGP → L3 routing with ECMP, but needs IP config, broadcast overhead. ECMP → uses all equal-cost paths, but local decisions may route to failed links temporarily. DCTCP → solves TCP incast/aggressive backoff with ECN proportional reduction, but not TCP-friendly, no flow prioritization, no slow-start fix. Each technique solves the previous limitation while introducing its own.
