01

VM Connection Methods

There are 3 ways to connect VMs to a network. They differ in where packet processing happens — software, hardware-assisted, or directly in the NIC.

① Virtual Switch

  • Pure software in hypervisor
  • All routing in software (CPU)
  • Easy, flexible, supports VLANs
  • Higher CPU overhead

② VMDq

  • Intel hardware tech
  • NIC sorts packets per-VM before CPU
  • Hypervisor still delivers packets
  • Reduces CPU overhead

③ SR-IOV

  • Physical NIC appears as multiple virtual NICs
  • Each VM gets its own Virtual Function (VF)
  • Bypasses hypervisor entirely via DMA
  • Lowest latency; limits live migration
📮 Post Office Analogy

No optimization: hypervisor reads every letter and walks to each VM.
VMDq: NIC pre-sorts letters into labeled mailboxes — hypervisor just delivers.
SR-IOV: each VM has its own private mailbox slot — hypervisor is completely bypassed.

02

Open vSwitch (OVS)

SOFTWARE SWITCH What is OVS?

The most popular virtual switch. It's a pure software switch embedded in the hypervisor. Every packet is routed in software — flexible but uses CPU cycles.

OVS has 3 components:

1
ovs-vswitchd (Userspace Daemon) Main switching daemon. Handles slow-path packet processing, switch configuration, and communicates with the kernel module.
2
ovsdb-server (Database Server) Stores persistent OVS configuration (bridges, ports, interfaces, flow rules). Survives reboots. Management tools communicate through this.
3
Kernel Module (openvswitch.ko) Handles fast-path packet forwarding. Caches flow rules from userspace for instant lookup. If a packet matches a cached rule → forward immediately. No match → send to userspace daemon.
FLOW How packet forwarding works
①
Packet first goes to userspace; the highest-priority matching rule is applied.
②
Once forwarded, a "collapsed rule" (fast shortcut) is installed in the kernel.
③
Future matching packets hit the kernel rule directly — no userspace trip needed. A hash value speeds up this lookup.
SDN SUPPORT OpenFlow Integration

OVS supports OpenFlow — an SDN protocol. An external SDN Controller pushes flow rules to OVS.

  • Match on: source/dest MAC, source/dest IP, TCP/UDP ports, VLAN tags, tunnel IDs, input port
  • Actions: forward to port, drop, modify headers, send to controller, forward to next flow table
03

VMDq & SR-IOV in Detail

VMDq Virtual Machine Device Queue
  • Intel hardware tech. NIC hardware sorts incoming packets into per-VM queues before the CPU sees them.
  • Hypervisor still delivers packets (uses VMBus), but sorting work is eliminated.
  • Multiple queues spread load across processor cores — better scalability.
  • Traffic still flows through the virtual switch.
SR-IOV Single Root I/O Virtualization
  • Physical NIC presents itself as multiple virtual NICs (Virtual Functions) to VMs.
  • Each VM gets a dedicated VF — traffic bypasses the hypervisor almost entirely via Direct Memory Access (DMA).
  • Extremely low latency and high throughput.
  • Downside: reduced flexibility for live VM migration (because the VM is tightly tied to hardware).
Key Difference: VMDq creates separate queues; SR-IOV creates separate virtual network devices (VFs). SR-IOV is faster and bypasses more of the stack.

VLAN Basics

VLAN Virtual LAN — What & Why

A VLAN is a virtual network on a physical LAN that groups nodes based on function, not physical location. Hosts in the same VLAN communicate as if on the same switch, even if physically apart.

  • Identified by a unique 12-bit VLAN ID (supports up to 4096 VLANs).
  • Membership can be based on: port, MAC address, protocol, IP subnet, or application.
IEEE 802.1Q Trunking / VLAN Tagging

When frames need to carry VLAN info across switches, 802.1Q adds a 4-byte tag into the Ethernet frame:

  • TPI (Tag Protocol ID): Always 0x8100 — marks the frame as 802.1Q tagged.
  • PCP (Priority Code Point): 3 bits for QoS/traffic priority (0–7).
  • CFI (Canonical Format Indicator): Always 0 for Ethernet (legacy compat).
  • VLAN ID: 12 bits → up to 4096 VLANs.
MISCONCEPTIONS VLAN vs Subnet — Not always 1:1
  • Common assumption: 1 VLAN = 1 subnet. Works fine for simple networks.
  • Two subnets can share one VLAN: they both get all broadcast/flooded frames. Unusual, but valid when you can't easily change IP addresses.
  • Two VLANs can share one subnet (more common in data centers): but a router can't tell them apart — use only when the two groups must never communicate.
Native VLAN Warning: Untagged frames go to the native VLAN (usually VLAN 1). This can allow VLAN 100 traffic to leak into VLAN 1. Best practice: tag ALL VLANs including the native one using vlan dot1Q tag native.
05

Private VLAN (PVLAN)

PVLAN What & Why

A PVLAN adds Layer 2 isolation within a single VLAN. Normally hosts on the same VLAN can all talk to each other. PVLAN restricts that — useful for providers hosting many tenants on the same subnet without re-IPing.

Use case: Same IP subnet, but you want some hosts to be isolated from each other (e.g., hotel guests, datacenter tenants).

STRUCTURE Primary & Secondary VLANs
  • Primary VLAN: The main VLAN visible to the outside network.
  • Secondary VLANs (Isolated or Community): Sub-VLANs inside the primary.

3 types of ports:

Promiscuous

Talks to ALL ports in the PVLAN. Usually the router/gateway.

Isolated

Can ONLY talk to promiscuous ports. Cannot reach other isolated or community ports.

Community

Can talk to other ports in the same community AND promiscuous ports. Cannot reach isolated ports or other communities.

CONFIG STEPS Setting up PVLAN
1
Create the primary VLAN.
2
Create secondary VLANs and set their type (isolated or community).
3
Associate secondary VLANs with the primary VLAN.
4
Assign switch ports to the appropriate VLAN type.
06

Layer 3 Switching & SVI

L3 SWITCH What is it?

A Layer 3 switch does both L2 switching AND L3 routing — in hardware. Unlike a normal switch, it can route traffic between VLANs without an external router.

SVI Switch Virtual Interface

An SVI is a logical interface on a Layer 3 switch tied to a VLAN. You assign it an IP address — it then acts as the default gateway for hosts in that VLAN.

SVI is only "up" when: (1) its associated VLAN exists AND (2) at least one active port belongs to that VLAN. The "autostate" feature controls this behavior.
NOTE SVI vs Routed Ports

You can also use routed ports on an L3 switch (like a router interface), but SVIs are generally preferred because they're more efficient and flexible for VLAN-based routing.

💡 Simple way to remember

Router-on-a-stick = one router interface with sub-interfaces per VLAN over a trunk link. L3 switch + SVI = cleaner, hardware-accelerated version of the same idea, built into the switch itself.

Tunneling Protocols — Overview

When VMs or customers need Layer 2 connectivity across Layer 3 networks, tunneling wraps L2 frames inside L3 packets. There are four main protocols covered:

Protocol Main Use Key Limitation
Q-in-Q (802.1ad) Service provider L2 VPN across metro networks Only 4096 customer IDs (12-bit VLAN)
MPLS WAN carrier-grade routing and VPNs Too complex/expensive for datacenter edge
VN-Tag Per-VM virtual Ethernet interfaces on switches Not universally recognized; may need further encapsulation
VXLAN Large-scale datacenter overlay networks UDP overhead; needs VTEP support
08

Q-in-Q / MPLS / VN-Tag

Q-in-Q IEEE 802.1ad — Double Tagging

A service provider technique where the provider adds an outer VLAN tag (their VLAN ID) around the customer's inner 802.1Q tag. The customer's VLAN is preserved transparently across the provider network.

  • Easy to implement — no routing protocols needed between SP and customer.
  • The outer 12-bit VLAN ID identifies the customer; the inner tag is the customer's own VLAN.
  • Only supports up to 4096 customers — too small for large cloud providers.
  • Access switch adds/removes the outer tag; forwarding uses MAC + outer VLAN tag.
# Customer router sub-interface int fa0/0.12 encapsulation dot1Q 12 ip address 192.168.12.1 255.255.255.0 # SP switch: enable Q-in-Q tunnel toward customer int fa0/1 switchport access vlan 123 switchport mode dot1q-tunnel
MPLS MultiProtocol Label Switching

Called a "Layer 2.5" protocol — sits between L2 and L3. Routers forward packets based on short fixed-length labels instead of IP addresses, making forwarding much faster.

  • LER (Label Edge Router): enters/exits MPLS network, assigns labels (push/pop).
  • LSR (Label Switching Router): interior routers that forward by label only.
  • LSP (Label Switched Path): unidirectional tunnel between LER pairs.
  • VPLS: MPLS-based L2 multi-point Ethernet service (MAC learning, flooding, broadcasts).
  • Not popular in cloud data centers — too complex and expensive at the edge.
VN-Tag Virtual NIC Tag (IEEE 802.1qbh)

Adds a virtual interface (VIF) identifier to frames so a switch can forward traffic to individual VMs even when they share the same physical switch port.

  • Traditional switches can't forward frames where source and destination are on the same port — VN-Tag solves this.
  • A single NIC can carry traffic for multiple VMs using different VIF tags.
  • Mainly used with fabric extenders. The controlling bridge assigns VIF IDs.
  • Not recognized by all equipment — may need further encapsulation.
STRETCHED VLAN

A VLAN extended across multiple physical sites over a Layer 3 WAN. L2 frames are encapsulated in L3 WAN packets. Allows VMs to migrate between sites without changing IP addresses.

09

VXLAN & NVGRE

VXLAN Virtual Extensible LAN — The Modern Solution

Proposed by Cisco and VMware. VXLAN tunnels Layer 2 (Ethernet) frames inside UDP/IP packets over a Layer 3 network — creating a massive overlay.

  • Solves VLAN's 4096 limit: uses a 24-bit VXLAN ID → up to 16 million virtual networks.
  • Provides L2 adjacency across L3 boundaries.
  • Supports overlapping IP addresses across tenants (logical isolation).
  • Minimizes forwarding table size on physical switches.
VTEP Virtual Tunnel Endpoint

The device (or software) that performs VXLAN encapsulation and decapsulation. Each VTEP maintains a table mapping inner VM MAC addresses → outer server IP addresses.

1
VM (Red 1) sends a frame to another VM (Red 2).
2
Source VTEP looks up Red 1 MAC → finds it maps to Server 2's IP.
3
VTEP encapsulates the L2 frame inside a VXLAN/UDP/IP packet and sends it over L3.
4
Destination VTEP strips the VXLAN header and delivers the original L2 frame to Red 2.
ENCAPSULATION VXLAN Frame Structure
Outer Ethernet Header
Outer IP Header + UDP Header (dest port 4789)
VXLAN Header (24-bit VNI — VXLAN Network Identifier)
Inner Ethernet Header (original L2 frame)
Original Payload (tenant data)
NVGRE Network Virtualization using GRE (Microsoft)
  • Microsoft's alternative to VXLAN — uses a GRE header instead of UDP+VXLAN header (slightly smaller frame).
  • Inner L2 header has no VLAN tag (removed before encapsulation).
  • The tunnel endpoint is called NVE (Network Virtual Endpoint) — part of Microsoft Hyper-V.
TUNNEL LOCATION Where does encapsulation happen?
LocationHowNotes
vSwitch VMware vSphere / NSX (VXLAN), Windows Server 2012 (NVGRE) Consumes CPU. Cannot use with SR-IOV.
NIC NIC hardware with tunnel offload support Few NICs support this; required if SR-IOV is in use.
ToR Switch Top-of-Rack switch acts as VTEP Traffic within same rack doesn't need tunneling — saves overhead.
SR-IOV + Tunneling: If SR-IOV is used (traffic bypasses vSwitch), tunneling MUST happen at the NIC or the ToR switch — not the vSwitch.

🧠 Big Picture

The whole module is about one problem: how do we connect virtual machines efficiently and securely, both within a datacenter and across sites? The methods go from simple software switches → hardware offload → full bypass (SR-IOV). The networking side goes from flat VLANs → isolation (PVLAN) → extending L2 across L3 (VXLAN). VXLAN wins in modern cloud because it scales to 16 million logical networks and works over any IP network.
