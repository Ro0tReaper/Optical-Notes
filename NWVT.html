01

VM Connection Methods

3 ways to connect VMs to a network — differing in where packet processing happens.

① Virtual Switch

  • Pure software in hypervisor
  • All routing done in software (CPU)
  • Easy, flexible, supports VLANs
  • Higher CPU overhead
  • Examples: VMware vSwitch, OVS

② VMDq

  • Intel hardware technology
  • NIC sorts packets into per-VM queues before CPU sees them
  • Hypervisor still delivers via VMBus
  • Reduces CPU overhead significantly

③ SR-IOV

  • Physical NIC presents as multiple virtual NICs
  • Each VM gets its own Virtual Function (VF)
  • Bypasses hypervisor entirely via DMA
  • Lowest latency; limits live migration
📮 Post Office Analogy (from the lecture)

No optimization: hypervisor reads every letter and walks to each VM — slow.
VMDq: NIC pre-sorts letters into labeled mailboxes; hypervisor just delivers.
SR-IOV: each VM has its own private mailbox slot; hypervisor is completely bypassed.

02

Open vSwitch (OVS)

WHAT IS IT Overview

The most popular virtual switch. A pure software switch embedded in the hypervisor. Supports VLANs, port mirroring, traffic shaping, OpenFlow/SDN integration. Higher CPU overhead than hardware-assisted methods.

3 COMPONENTS OVS Architecture
1
ovs-vswitchd (Userspace Daemon) Main switching daemon. Handles slow-path packet processing and switch configuration. Communicates with the kernel module via Netlink.
2
ovsdb-server (Database Server) Stores persistent OVS config (bridges, ports, interfaces, flow rules). Survives reboots. Management tools connect to it via port 6632/TCP.
3
Kernel Module (openvswitch.ko) — Fast Path Handles fast-path packet forwarding. Caches flow rules from userspace for instant lookup. On match → forward immediately. No match → send to userspace daemon.
PROTOCOLS OVS Communication Channels WAS MISSING

Management Protocol

Port 6632/TCP. Used by management tools (like ovs-vsctl) to communicate with ovsdb-server.

OpenFlow Protocol

Port 6633/TCP. Used by an external SDN Controller to push flow rules to ovs-vswitchd.

Netlink

In-kernel communication. Used by ovs-vswitchd (userspace) to communicate with the OVS Kernel Module.

FLOW TABLE STRUCTURE How OVS matches packets WAS MISSING

OVS maintains multiple flow tables. Each table has rules with match fields and actions:

  • First packet: goes to userspace. The highest-priority matching rule is applied.
  • Collapsed rule: once forwarded, a shortcut rule combining all match fields (srcMAC + dstMAC + dstIP + dstTCPPort → action) is installed in the kernel.
  • Subsequent packets: hit the kernel rule directly — no userspace needed. A hash value speeds up lookup.

The kernel table has columns: srcMAC | dstMAC | dstIP | dstTCPPort | action

FEATURES OVS Layer 2 & Layer 3
  • L2: MAC learning and forwarding, VLAN tagging/trunking (802.1Q), STP (Spanning Tree Protocol), LACP (Link Aggregation), port mirroring
  • L3: Basic IPv4/IPv6 routing, ARP proxying, Tunnel encapsulation/decapsulation
  • SDN: OpenFlow support — match on src/dst MAC, src/dst IP, TCP/UDP ports, VLAN tags, tunnel IDs, input port. Actions: forward to port, drop, modify headers, send to controller, next flow table.
03

VMDq & SR-IOV in Detail

VMDq Virtual Machine Device Queue
  • Intel hardware tech. NIC sorts incoming packets into per-VM queues before the CPU sees them.
  • Multiple queues spread load across processor cores → removes processing bottleneck.
  • Hypervisor still delivers packets using VMBus. Traffic still goes through the virtual switch.
  • Reduces vSwitch workload and enables better scalability. (See diagram: VM → vNIC → vSwitch → NIC with VMDq queues)
SR-IOV Single Root I/O Virtualization
  • Physical NIC presents itself as multiple Virtual Functions (VFs) — one per VM.
  • Also contains one Physical Function (PF) for the host/hypervisor control.
  • An internal L2 sorter (switch) inside the NIC routes traffic to the right VF.
  • VM communicates directly with its VF via DMA (Direct Memory Access) — bypasses the vSwitch entirely.
  • Extremely low latency and high throughput. Downside: limits live VM migration.
Key difference from VMDq: VMDq = separate queues, hypervisor still involved. SR-IOV = separate virtual network devices (VFs), hypervisor bypassed entirely.

VLAN Basics & Trunking

VLAN What & Why

Groups nodes by function, not physical location. Hosts in the same VLAN communicate as if on the same switch. Identified by a 12-bit VLAN ID (max 4096). Membership can be by port, MAC, protocol, IP subnet, or application.

IEEE 802.1Q Trunking / VLAN Tagging

Adds a 4-byte tag to Ethernet frames so VLAN info is carried across switches (trunk links):

  • TPI (Tag Protocol ID): 0x8100 — marks frame as 802.1Q tagged.
  • PCP (Priority Code Point): 3 bits for QoS/traffic priority (0–7, IEEE 802.1p).
  • CFI (Canonical Format Indicator): Always 0 for Ethernet (legacy Token Ring compat).
  • VLAN ID: 12 bits → up to 4096 VLANs.

Router-on-a-Stick WAS MISSING

CONCEPT What is Router-on-a-Stick?

A way to route between VLANs using a single physical router interface with multiple sub-interfaces — one per VLAN. The router connects to the switch via a trunk link. Each sub-interface handles one VLAN.

COMMANDS Router Sub-Interface Config WAS MISSING
! Figure 3-7: Router-on-a-Stick for inter-VLAN routing ! Sub-interface for VLAN 101 Router# show running-config interface GigabitEthernet 0/0.101 interface GigabitEthernet0/0.101 encapsulation dot1Q 101 ip address 10.1.1.100 255.255.255.0 end ! Sub-interface for VLAN 201 Router# show running-config interface GigabitEthernet 0/0.201 interface GigabitEthernet0/0.201 encapsulation dot1Q 201 ip address 10.2.2.200 255.255.255.0 end

Each sub-interface gets the VLAN tag (encapsulation dot1Q) and an IP address. The connected switch port must be a trunk allowing those VLANs.

💡 Router-on-a-stick vs L3 Switch

Router-on-a-stick = external router with sub-interfaces, software routing, one trunk cable. L3 Switch + SVI = same concept built into the switch hardware — faster, more scalable, preferred in data centers.

Two Common VLAN Misconceptions

MYTH 1 One VLAN always = One Subnet
  • Common assumption: each VLAN maps to exactly one IP subnet. Works fine for simple networks.
  • Two subnets can share one VLAN: both get all broadcast/flooded frames. Unusual but valid when you can't change IP addresses (e.g., service provider networks).
MYTH 2 One Subnet always fits in One VLAN
  • Two VLANs can share one IP subnet — more common in data centers (e.g., voice and data on same addresses, must never talk to each other).
  • A router sees both as the same network and cannot distinguish them — only works if the two groups never need to route to each other.

Spanning Tree Protocol (STP) & VLANs WAS MISSING

STP Why it matters with VLANs

When multiple switches are interconnected (for redundancy), Layer 2 loops can form — causing broadcast storms. Spanning Tree Protocol (STP) prevents this by automatically blocking redundant paths and maintaining only a loop-free topology.

  • STP elects a Root Bridge — all other switches calculate the shortest path to it.
  • Redundant links are placed in a blocking state; only the best path stays active.
  • If an active link fails, STP recalculates and unblocks a previously blocked path.
  • In VLAN environments, each VLAN can run its own STP instance (PVST+ / Rapid PVST+) allowing different VLANs to use different paths for load balancing.

Private VLAN (PVLAN)

CONCEPT What & Why

Adds Layer 2 isolation within a single VLAN — same IP subnet, restricted communication. Useful for providers hosting many tenants, or datacenter security where servers shouldn't reach each other directly.

STRUCTURE Primary + Secondary VLANs
  • Primary VLAN (e.g. VLAN 100): The visible VLAN to the outside network. Associated with secondary VLANs.
  • Isolated Secondary VLAN (e.g. VLAN 101): Ports can only talk to promiscuous ports.
  • Community Secondary VLAN (e.g. VLAN 102): Ports talk to each other in the community + promiscuous ports.

Promiscuous Port

Talks to ALL ports in the PVLAN. Typically the router/gateway/firewall.

Isolated Port

Can ONLY talk to promiscuous ports. Cannot reach any other isolated or community host.

Community Port

Talks to other ports in same community + promiscuous ports. Blocked from isolated and other communities.

Layer 3 Switch & SVI

L3 SWITCH What is it?

A switch that does both L2 switching and L3 routing in hardware. Uses Switch Virtual Interfaces (SVIs) to route between VLANs without an external router. You can also use routed ports (IP directly on a port like a router), but SVIs are preferred.

SVI UP CONDITIONS

An SVI is only up when BOTH of these are true simultaneously:

  • Its associated VLAN exists in the switch database.
  • At least one active port (access or trunk) belongs to that VLAN.

The autostate feature (Cisco) controls whether the SVI state tracks active ports or stays up manually.

Q-in-Q / MPLS / VN-Tag / Stretched VLAN

Q-in-Q IEEE 802.1ad — Double VLAN Tagging

Service provider adds an outer VLAN tag (SP's VLAN) around the customer's inner 802.1Q tag. Customer VLANs pass transparently across the SP network.

  • Easy to implement — no routing protocols needed between SP and customer.
  • Outer 12-bit VLAN ID = customer identifier. Inner tag = customer's own VLAN.
  • Only 4096 customers max — not suitable for large clouds.
  • Used in Metro Ethernet (E-LINE / E-LAN) and Transparent Firewall/IPS setups.
  • Added/removed by the access switch. Forwarding uses MAC + outer VLAN tag.

MPLS MultiProtocol Label Switching — "Layer 2.5"
  • Introduced late 1990s. Works with IPv4 and IPv6.
  • LER (Label Edge Router): enters/exits MPLS network. Pushes or pops labels. Makes initial path selection.
  • LSR (Label Switching Router): interior transit routers. Forward by label only — no IP lookup.
  • LSP (Label Switched Path): unidirectional tunnel between a pair of LERs — required for any MPLS forwarding.
  • VPLS: MPLS-based multi-point Ethernet service (MAC learning, flooding, broadcasts across MPLS).
  • Not popular in cloud data centers — too complex and expensive at the edge. Tunneling in vSwitch consumes server CPU.
VN-Tag IEEE 802.1qbh — Virtual NIC Tagging
  • Adds a VIF (Virtual Interface) identifier to frames so a switch can forward to individual VMs on the same physical port.
  • Traditional switches can't forward frames where source and destination are on the same port. VN-Tag fixes this.
  • A single NIC can carry multiple VM traffic streams using different VIF tags.
  • Used mainly with fabric extenders. The controlling bridge assigns VIF IDs.
  • Not universally recognized — may need further encapsulation in the datacenter network.
STRETCHED VLAN

A VLAN extended across multiple physical sites over an L3 WAN. L2 frames are encapsulated in L3 WAN packets. Allows VMs to live-migrate between sites without changing their IP address or network configuration.

VXLAN & NVGRE

VXLAN Virtual Extensible LAN — The Modern DC Solution

Proposed by Cisco and VMware. Tunnels Layer 2 Ethernet frames inside UDP/IP packets over Layer 3. Creates a massive overlay solving VLAN's 4096 limit.

  • 24-bit VXLAN Network Identifier (VNI) → up to 16 million virtual networks.
  • Provides L2 adjacency across L3 boundaries.
  • Supports overlapping IP addresses across tenants (logical isolation per VNI).
  • Minimizes forwarding table size on physical switches.
  • UDP destination port: 4789.
ENCAPSULATION VXLAN Frame Stack
Outer Ethernet Header (physical network MAC addresses)
Outer IP Header + UDP Header (dest port 4789)
VXLAN Header (8 bytes — contains 24-bit VNI)
Inner Ethernet Header (original tenant L2 frame)
Original Payload (tenant data)
VTEP Virtual Tunnel Endpoint — How forwarding works

The VTEP maintains a table mapping inner VM MAC → outer server IP. Packet flow:

1
VM (Red 1) sends a frame to another VM (Red 2) on a different physical server.
2
Source VTEP looks up Red 1's MAC → finds it maps to Server 2's IP address.
3
VTEP encapsulates the L2 frame: wraps it in VXLAN header + UDP + outer IP, sends over L3 network.
4
Destination VTEP strips VXLAN header, delivers original L2 frame to Red 2. Red 2 never knows it crossed an L3 boundary.
TUNNEL LOCATION Where does VTEP/encapsulation live?
LocationExamplesNotes
vSwitchVMware vSphere/NSX (VXLAN), Windows Server 2012 (NVGRE)Consumes CPU. Cannot use with SR-IOV.
NICNICs with tunnel offload hardwareFew NICs support this; required if SR-IOV bypasses the vSwitch.
ToR SwitchTop-of-Rack switch acts as VTEPTraffic within same rack skips tunneling — saves overhead.
NVGRE Network Virtualization using GRE (Microsoft)
  • Microsoft's alternative to VXLAN. Uses a GRE header instead of UDP+VXLAN header — slightly smaller frame.
  • Inner L2 header has no VLAN tag (removed before encapsulation).
  • Tunnel endpoint called NVE (Network Virtual Endpoint) — part of Microsoft Hyper-V.

🧠 Big Picture — How it all connects

The whole module answers: how do we connect VMs efficiently, scalably, and securely?
Compute side: vSwitch (flexible) → VMDq (hardware sort) → SR-IOV (hardware bypass).
Network side: VLAN (basic isolation) → PVLAN (isolation within VLAN) → Stretched VLAN / VXLAN (extend L2 across L3).
VXLAN wins in modern cloud because it scales to 16M networks, works over any IP underlay (OSPF/BGP), and the VTEP can live in software or hardware. The lab shows exactly how to wire it up on Cisco NX-OS.
