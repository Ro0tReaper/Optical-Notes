Correct: B. Tim O'Reilly popularised the term "Web 2.0" to describe the second phase of the web where users could read AND write content (social web). Web 3.0/Semantic Web was envisioned by Tim Berners-Lee.

B Deep Web

D Visible Web
Correct: C. The Dark Web requires special software (like Tor) to access and is often associated with illegal activity (e.g., Silk Road). Deep Web is not indexed but includes legitimate sites like Netflix, Gmail that require login.

B POST

QUESTION 11 MEDIUM
XSS

A Input filtering alone
B Output escaping (contextual encoding)
C Using HTTPS
D Disabling JavaScript in the browser
Correct: B. Output escaping (converting < to &lt;, > to &gt;) is the PRIMARY defence. Input filtering is secondary defence-in-depth. HTTPS doesn't prevent XSS. You can't control user browser settings.
QUESTION 12 MEDIUM

QUESTION 13 MEDIUM

Correct: A. XSS = malicious script runs in victim's browser (fools client). CSRF = legitimate browser makes unintended request, server accepts it because cookie is valid (fools server). CSRF does NOT require JavaScript.

QUESTION 15 MEDIUM

B Tricking a victim into using an attacker-chosen session ID

Correct: B. Session fixation: Attacker gets a session ID, tricks victim into using it (via URL or cookie), victim logs in, server associates that ID with victim's privileges, attacker uses same ID to access victim's account. Fix: Always generate NEW session ID on login.

QUESTION 01 EASY
SQL Injection Prevention
Rewrite this vulnerable login code to prevent SQL injection:
$username = $_POST['username']; $password = $_POST['password']; $sql = "SELECT * FROM users WHERE username='$username' AND password='$password'"; $result = mysqli_query($conn, $sql);
✓ Secure Solution
$username = $_POST['username']; $password = $_POST['password']; $stmt = $conn->prepare("SELECT * FROM users WHERE username = ? AND password = ?"); $stmt->bind_param("ss", $username, $password); $stmt->execute(); $result = $stmt->get_result();
Key points: Use prepared statements with parameterized queries. The SQL structure is compiled first, then data is bound - injected SQL in data cannot alter the query structure. Never use string concatenation for SQL.
QUESTION 02 EASY
XSS Prevention
Rewrite this code to prevent XSS when displaying user comments:
$comment = $_GET['comment']; echo "<div class='comment'>$comment</div>";
✓ Secure Solution
$comment = $_GET['comment']; echo '<div class="comment">' . htmlspecialchars($comment, ENT_QUOTES, 'UTF-8') . '</div>';
Key points: Use htmlspecialchars() with ENT_QUOTES flag to escape <, >, &, ", and '. Specify UTF-8 encoding. This is output escaping - the PRIMARY defence against XSS.

QUESTION 06 EASY
File Upload
Add security checks to this file upload code:
$file = $_FILES['avatar']; move_uploaded_file($file['tmp_name'], "uploads/" . $file['name']);
✓ Secure Solution
$allowedTypes = ['image/jpeg', 'image/png', 'image/gif']; $maxSize = 2 * 1024 * 1024; // 2MB if (!isset($_FILES['avatar']) || $_FILES['avatar']['error'] !== UPLOAD_ERR_OK) { die("Upload failed"); } $file = $_FILES['avatar']; // Check file size if ($file['size'] > $maxSize) { die("File too large"); } // Check MIME type using finfo (NOT the browser-provided type) $finfo = new finfo(FILEINFO_MIME_TYPE); $mimeType = $finfo->file($file['tmp_name']); if (!in_array($mimeType, $allowedTypes)) { die("Invalid file type"); } // Generate safe filename (never use user-provided name) $ext = pathinfo($file['name'], PATHINFO_EXTENSION); $newName = bin2hex(random_bytes(16)) . "." . $ext; // Store outside web root if possible $destination = "/var/uploads/avatars/" . $newName; move_uploaded_file($file['tmp_name'], $destination);
Key points: Check MIME type with finfo (not browser-provided), limit size, generate random filename, store outside web root. Never trust file extension alone.
QUESTION 07 MEDIUM
CSRF Protection
Add CSRF protection to this form processing:
if ($_SERVER['REQUEST_METHOD'] === 'POST') { $amount = $_POST['amount']; $to = $_POST['recipient']; transferMoney($to, $amount); }
✓ Secure Solution
if ($_SERVER['REQUEST_METHOD'] === 'POST') { // Verify CSRF token if (!isset($_POST['csrf_token']) || !hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) { die("Invalid request"); } $amount = filter_input(INPUT_POST, 'amount', FILTER_VALIDATE_FLOAT); $to = filter_input(INPUT_POST, 'recipient', FILTER_SANITIZE_STRING); if ($amount && $to) { transferMoney($to, $amount); // Regenerate token after use $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); } } // Generate token for form (call this when rendering the form) function generateCsrfToken() { if (empty($_SESSION['csrf_token'])) { $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); } return $_SESSION['csrf_token']; }
Key points: Use cryptographically secure random token, store in session, verify with hash_equals() (timing-safe comparison), regenerate after use. Include token as hidden field in form.
QUESTION 08 MEDIUM
Command Injection Prevention
Secure this code that runs a system command with user input:
$filename = $_GET['file']; $output = shell_exec("ls -la /var/www/files/$filename"); echo "<pre>$output</pre>";
✓ Secure Solution
// Option 1: Whitelist allowed filenames (BEST) $allowedFiles = ['readme.txt', 'config.json', 'help.html']; $filename = $_GET['file'] ?? ''; if (!in_array($filename, $allowedFiles, true)) { die("Invalid file"); } $output = shell_exec(escapeshellcmd("ls -la /var/www/files/" . escapeshellarg($filename))); echo '<pre>' . htmlspecialchars($output, ENT_QUOTES, 'UTF-8') . '</pre>'; // Option 2: Use PHP's built-in functions instead (BETTER) $filepath = "/var/www/files/" . basename($filename); if (is_file($filepath) && is_readable($filepath)) { echo nl2br(htmlspecialchars(file_get_contents($filepath), ENT_QUOTES, 'UTF-8')); }
Key points: Best approach: avoid shell commands entirely, use PHP's built-in functions. If shell is required: use whitelist, escapeshellarg() for arguments, escapeshellcmd() for command, and basename() to prevent path traversal.
QUESTION 09 MEDIUM
Session Security
Secure this session initialization code:
session_start(); if (!isset($_SESSION['logged_in'])) { $_SESSION['logged_in'] = false; }
✓ Secure Solution
// Configure session before starting ini_set('session.use_strict_mode', '1'); ini_set('session.use_only_cookies', '1'); ini_set('session.cookie_httponly', '1'); ini_set('session.cookie_secure', '1'); ini_set('session.cookie_samesite', 'Strict'); ini_set('session.gc_maxlifetime', '3600'); // 1 hour idle timeout session_start(); // Regenerate session ID to prevent fixation if (empty($_SESSION['initiated'])) { session_regenerate_id(true); $_SESSION['initiated'] = true; $_SESSION['created'] = time(); $_SESSION['last_activity'] = time(); } // Check idle timeout if (time() - $_SESSION['last_activity'] > 3600) { session_destroy(); header("Location: login.php?expired=1"); exit(); } $_SESSION['last_activity'] = time(); // Check absolute timeout (e.g., 24 hours max) if (time() - $_SESSION['created'] > 86400) { session_destroy(); header("Location: login.php?expired=1"); exit(); }
Key points: Set secure cookie flags, use strict mode, regenerate ID on first use, implement both idle and absolute timeouts, track last activity.
QUESTION 10 MEDIUM
Password Hashing
Securely hash a password for storage:
$password = $_POST['password']; $hashed = md5($password); $sql = "INSERT INTO users (password_hash) VALUES ('$hashed')";
✓ Secure Solution
$password = $_POST['password']; // Validate password meets complexity requirements if (strlen($password) < 8) { die("Password must be at least 8 characters"); } // Hash with bcrypt (automatically handles salt) $hashed = password_hash($password, PASSWORD_BCRYPT, [ 'cost' => 12 // Adjust based on server performance ]); // Store using prepared statement $stmt = $conn->prepare("INSERT INTO users (password_hash) VALUES (?)"); $stmt->bind_param("s", $hashed); $stmt->execute(); // Verification (for login): // if (password_verify($inputPassword, $storedHash)) { ... }
Key points: NEVER use MD5/SHA-1 for passwords. Use password_hash() with PASSWORD_BCRYPT or PASSWORD_ARGON2ID. Salt is automatic. Use prepared statement for storage.
QUESTION 11 MEDIUM

QUESTION 12 MEDIUM
Directory Traversal Prevention
Secure this file download code:

''; if (!isset($allowedFiles[$file])) { http_response_code(404); die("File not found"); } $path = $allowedFiles[$file]; // Option 2: If dynamic paths needed, use basename() and validate $file = basename($_GET['file'] ?? ''); // Removes path components $basePath = "/var/www/downloads/"; $path = $basePath . $file; // Verify path is within base directory (canonicalize first) $realBase = realpath($basePath); $realPath = realpath($path); if ($realPath === false || !str_starts_with($realPath, $realBase)) { http_response_code(403); die("Access denied"); } if (is_file($realPath)) { header('Content-Type: application/octet-stream'); header('Content-Disposition: attachment; filename="' . basename($realPath) . QUESTION 13 MEDIUM
Error Handling
Secure this database error handling:
$result = $conn->query($sql); if (!$result) { echo "Error: " . $conn->error; }

" | Query: " . $sql); // Show generic error to user http_response_code(500); echo "An error occurred. Please try again later."; exit; } // Better: Set up global error handler mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT); try { $result = $conn->query($sql); } catch (mysqli_sql_exception $e) { error_log("DB Error: " . $e->getMessage()); http_response_code(500); echo "An error occurred. QUESTION 14 MEDIUM
Open Redirect Prevention
Secure this redirect code:

✓ Secure Solution
