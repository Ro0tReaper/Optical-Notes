Introduction to the Web

What is the WWW?

A system of interlinked hypertext documents that runs over the Internet. Users view web pages (text, images, multimedia) and navigate with hyperlinks.

Created ~1990 by Tim Berners-Lee and Robert Cailliau at CERN, Geneva, Switzerland.

Hypertext / Hyperlink

Clickable links connecting resources across the web. Uses URI / URL (Uniform Resource Identifier / Locator) to identify resources.

Protocols: http:// or ftp://

Example: http://somehost/path/resource.txt

Markup Language

Characters or codes embedded in text that indicate structure, semantic meaning, or presentation advice.

Example: HTML tags like <h1>, <p>, <a>

Web 1.0 → Web 2.0 → Web 3.0

Web 1.0 — "Crawl" (Read-Only Web)

Pages were static and read-only. Users consumed content, they couldn't create it. Resources linked via hyperlinks (href). Company-focused. Home pages, directories, HTML/Portals, banner advertising, page-view metrics.

Web 2.0 — "Walk" (Social Web)

Term popularised by Tim O'Reilly. A "second phase" of architecture — users can now read AND write. Ordinary users meet, collaborate, and share via social software.

Examples: Wikipedia, Flickr, Google Maps, del.icio.us, digg, Skype, orkut.

6 Key Principles:

The Web as Platform Data is the next "Intel Inside" End of Software Release Cycles Lightweight Programming Models Software Above a Single Device Rich User Experiences

Web 3.0 — "Run" (Semantic Web)

Vision by Tim Berners-Lee. The web gains machine-understandable semantics. Computers reason over information automatically.

"An extension of the current Web in which information is given well-defined meaning, better enabling computers and people to work in cooperation."
— Tim Berners-Lee et al., Scientific American, 2001

Uses: Semantic Searching — search augmented with related activities, recommendations, and contextual information.

Surface Web / Deep Web / Dark Web

Think of the web as an iceberg. All three layers are part of the Internet.

Surface Web

Publicly visible, indexed by search engines (Google, Bing).

e.g. Wikipedia, BBC, Facebook public pages, Amazon, CNN

Deep Web

Not indexed by search engines. Requires login or credentials.

e.g. LinkedIn (private), Netflix, PayPal, Dropbox, Gmail, Bank of America, WhatsApp, JPMorgan

Dark Web

Requires special software (like Tor) to access. Often illegal activity.

e.g. Silk Road, AlphaBay Market, DuckDuckGo (onion), ProPublica (onion)

Static Websites

What is it?

A site with fixed content written in HTML. Every page is coded and saved separately on the server. Changes must be made manually and require coding knowledge.

Static files are published by physical transfer from the developer's PC to the web hosting computer. The client sends a Request → server responds with a static HTML document.

Typical Structure

Header (Logo, Menu, Icons) Side Bars Content / Body Footer (Links, Icons)

✓ Advantages

  • Easy to develop
  • Cheap to develop
  • Cheap to host

✗ Disadvantages

  • Requires coding expertise to update
  • Changes are very time-consuming
  • Less useful for the user
  • Content gets stagnant / out of date
5

Dynamic Websites

What is it?

A site controlled by an application server using server-side scripts. Pages are not coded separately — the design/template and content are stored separately, then the page is dynamically populated on every request.

Server → queries Database → dynamically builds the page → sends it to the Client/Browser.

File Extensions Used

.jsp .cfm .pl .php .asp .aspx

Can leverage company databases, spreadsheets, and text files as web content. Pages support full CRUD operations:

Create Retrieve Update Delete

Dynamic Page Structure

A single request dynamically fills all sections from a template file:

Header (Logo, Icons) Menu Content / Body Side Bars Footer (Links, Icons)

✓ Advantages

  • Much more functional
  • Much easier to update
  • Easy to add new content/pages
  • Fresh content helps SEO & brings users back
  • Staff/users can collaborate

✗ Disadvantages

  • More expensive to develop
  • Slower to develop
  • Hosting costs slightly more (though less true now with shared hosting plans)

Content Management Systems (CMS)

Web Content Management System (WCMS)

A CMS designed to simplify publishing web content, allowing content creators to submit content without needing HTML knowledge or manual file uploads.

Popular CMS examples:

WordPress Joomla Drupal nopCommerce DotNetNuke Magento

Static vs. Dynamic — Which to Choose?

Choose Static When…

  • 📦 Limited budget / starting a basic web presence
  • 📄 20 pages or fewer
  • 🗓️ Planning to add new pages only occasionally
  • 👨‍💻 Skilled staff or an assigned provider handles updates
  • 💾 Need portable, physical web page files

Choose Dynamic When…

  • ⚙️ Need custom programming for unique business needs
  • 🔌 Pages must pull data from external sources
  • ✏️ Need to add/edit pages easily from a browser
  • 🗄️ Pages display & update records from info systems
  • 👥 Multiple staff members need edit access
  • 🛒 Need blogs, events, login, ecommerce, article publishing

Technologies Every Web Developer Should Know

Browsers

Browsers are the interpreters of the web. They send requests, receive responses, and render pages.

Google Chrome — most popular Safari — Apple Firefox — open-source (Mozilla) Internet Explorer — Microsoft (developers complain about this one)

HTML — HyperText Markup Language

The standard markup language for creating web pages. Provides the structure of a website so browsers know what to display.

HTML = Structure of the page

CSS — Cascading Style Sheet

A style sheet language that describes the presentation of HTML documents. Controls colors, fonts, animations, and transitions — it makes the web look good.

CSS = Visual appearance of the page

Programming Languages

Ways to communicate with computers and tell them what to do.

🖥 Server-Side

ASP.NET PHP JSP Ruby

🌐 Client-Side

JavaScript

Frameworks

Built on top of programming languages to make development easier. Handle repetitive tasks in setting up a web app — either doing them for you or simplifying them.

Drupal WordPress Node.js

Libraries

Pre-written code collections that developers can use to add functionality without writing from scratch. (Mentioned in the lecture outline alongside frameworks.)

Databases

Where all data is stored. Two main types:

SQL — Structured

More structure → ensures data is correct and validated.

MySQL Oracle SQL Server

NoSQL — Flexible

More flexibility for building and maintaining applications.

MongoDB

Client (Client-Side)

One user of an application. Can be a desktop computer, tablet, or mobile device. Multiple clients interact with the same server-side application simultaneously.

Client sends HTTP Request → Server sends HTTP Response

Server (Server-Side)

Where the application code is stored. Receives requests from clients, gathers the appropriate information, and sends back responses. Often includes a database (e.g. MySQL).

Example flow: Browser → Internet → Web server (PHP interpreter + MySQL db) → back to browser as HTML

Front-End

Everything the user sees in the browser. Built with HTML, CSS, and JavaScript. Focused on user interface and experience.

Back-End

Everything that happens on the server. Business logic, databases, authentication. Users never directly see this.

Protocols

Rules that define how data is transmitted over the network. The web primarily uses:

HTTP — HyperText Transfer Protocol (web pages) FTP — File Transfer Protocol (file uploads)

API — Application Programming Interface

Created by a developer to let other developers use some functionality of an application without sharing the underlying code.

Facebook API Twitter API Google API

Data Formats

The structure used to store and transmit data.

XML — eXtensible Markup Language JSON — JavaScript Object Notation CSV — Comma-Separated Values
